# Course entry navigation

Syllabus and lecture-note entries use the same quiet, borderless visual rhythm. Note and module entries remain one ordered region. There is no visible drag handle: desktop users drag the entry surface using the browser’s native threshold, with reordering committed only after at least six pixels of movement. Three-pixel movement remains an ordinary click. Early native dragstart is never cancelled solely for starting before six pixels, so slow dragging can continue. Editable fields, icon menus, media controls and an existing text selection cannot start row reordering. Alt+Up/Down on a focused row and the row's movement menu provide keyboard/touch alternatives. Reordering preserves source IDs, document bodies, archived entries and widths.

The existing project icon popover is reused with its entire supported catalog, search, categories and pagination. It supports an optional immediate-persist callback for course entries, retaining the normal project form behavior. Icon grids are loaded when opened so sixteen notes do not eagerly render sixteen hidden catalogs. A choice persists immediately without another Save button; failed saves restore the prior choice and show the existing actionable save error. Existing emoji data remains stored and displayed until an icon is selected. Stored icon IDs are validated against the same catalog.

Isolated browser fixtures verify immediate icon selection/reload/failure retry, legacy preservation, native mixed note/module drag, keyboard/mobile reorder, small-motion click/back, text selection guard, quiet surfaces and desktop/mobile widths. The original project appearance browser check verifies no regression in project color/icon settings, keyboard and Escape behavior. No live course or file is modified.
