# Studio UI Language

이 문서는 Studio와 같은 제품군 앱이 공유할 시각·상호작용 언어의 기준이다. Studio에만 필요한 정보 구조와 업무 흐름은 제품 패턴으로 구분한다. 새 화면은 공통 토큰과 컴포넌트를 우선 사용하고, 새로운 전역 규칙은 이 문서와 구현을 함께 갱신한다.

Studio의 UI 원칙은 **Glanceable · Calm · Contextual · Connected · Shoot-friendly**다. 화면은 현재 상태와 다음 행동, 핵심 업무 정보, 보조 설명, 관리 메타데이터 순으로 읽힌다. 정보는 풍부하게 보여주되 장식은 업무 판단에 도움이 될 때만 쓴다.

## 1. Visual foundations

### Color

기본 화면과 대부분의 패널은 흰색 바탕이다. 보조 표면은 차가운 중성 회색을 쓰며, 선택 상태에는 옅은 파랑을 사용한다. 좌측 워크스페이스 레일은 흰색과 구분되는 옅은 회색이다. 색상은 상태, 선택, 프로젝트 식별처럼 의미가 있을 때 사용한다.

| 역할 | CSS 변수 | 현재 값 |
| --- | --- | --- |
| 앱·카드 표면 | --bg, --surface | #fff |
| 보조 표면 | --surface-2 | #f4f5f7 |
| 기본 글자·강조 | --ink, --accent | #18181b |
| 보조 글자 | --muted | #71717a |
| 구분선 | --line | #e7e7eb |
| 선택 항목 배경 | --selected | #f0f5ff |
| 준비 완료 | --ok | #2f6b48 |
| 확인 필요 | --warn | #8a641d |
| 문제 있음 | --bad | #a13b32 |

프로젝트 및 배치 아이덴티티 색상은 6색 팔레트로 제한한다: 보라 #8858ef, 파랑 #4384ee, 주황 #ff812c, 초록 #2d9b73, 분홍 #df5f94, 회색 #535660. 이 팔레트는 의미가 아니라 식별을 위한 색상이다.

상태는 색만으로 표현하지 않는다. 읽을 수 있는 레이블을 함께 쓰고 필요한 경우 아이콘이나 모양을 보탠다. 기본 상태 어휘는 **준비 완료 / 확인 필요 / 문제 있음 / 미정**이다. 주요 동작은 진한 잉크색 버튼, 보조 동작은 흰색 테두리 버튼, 덜 중요한 동작은 투명 버튼으로 표시한다. 위험한 동작은 명확한 확인 문구와 붉은색 계열로 구별한다.

### Typography

글꼴 스택은 Inter를 우선 사용하고 Apple·BlinkMac·Segoe UI 시스템 글꼴로 대체한다. 별도 폰트 파일은 저장소에 포함되어 있지 않다. 아래 역할 토큰을 기준으로 하며, 작은 화면이라고 탭이나 제목 글자를 임의로 줄이지 않는다. 표의 px 값은 브라우저 기본 글자 크기 16px 기준이다.

| 역할 | CSS 변수 | 크기 | 대표 사용처 |
| --- | --- | --- | --- |
| 페이지 제목·핵심 수치 | --text-page, --text-metric | 22px / 1.375rem | 화면 제목, 준비도와 통계 |
| 섹션 제목 | --text-section | 16px / 1rem | 화면 내 구역 제목 |
| 카드·상단바 제목 | --text-title | 15px / .9375rem | 카드, 프로젝트, 사이드바 제목 |
| 기본 본문·조작 | --text-body | 13px / .8125rem | 탭, 버튼, 목록 이름, 라벨 |
| 보조 설명 | --text-support | 12px / .75rem | 설명, 시간, 담당자, 도움말 |
| 메타 정보 | --text-meta | 11px / .6875rem | 상태 배지, 통계 라벨, 저장 상태 |

기본 본문 행간은 1.5, 보조 설명은 1.6, 카드 제목은 약 1.4, 페이지 제목은 약 1.3을 사용한다. 일반 글자 두께는 400, 제목·선택 상태·강조는 500을 기본으로 한다. 글자 크기는 rem 토큰을 사용해 사용자 확대 설정을 존중한다. 모바일의 텍스트 입력은 브라우저 확대 방지를 위해 16px로 표시한다.

화면 문구는 짧고 구체적인 한국어 동사형을 우선한다. 제목이 이미 설명하는 정보를 반복하지 않는다. 권한, 만료, 입력 제한, 저장 실패와 복구처럼 사용자가 다음 행동을 결정하는 정보는 해당 위치에 남긴다.

### Shape, spacing and elevation

모서리는 둥근 사각형을 기본으로 하고 corner-shape: squircle을 지원하는 브라우저에서는 연속 곡률을 적용한다. 구현은 항상 border-radius 대체값을 먼저 제공한다. 실제 공통 반경 토큰은 --r-control 9px, --r-surface 14px, --r-panel 20px다. 배지처럼 원형이 의미를 갖는 요소와 캔버스 오브젝트는 해당 패턴의 형상을 유지한다. 별도의 --r-hero 같은 토큰은 현재 없다.

공통 여백 토큰은 4px 단위의 4, 8, 12, 16, 20, 24, 32px이다. 페이지별 배치가 이를 무시해야 한다면 기존 패턴의 예외인지 확인하고 예외를 국소화한다. 기본 표면은 1px 구분선과 매우 옅은 그림자를 사용한다. 모달은 표면보다 강한 그림자와 반투명 오버레이로 전후 관계를 분명히 한다.

| 용도 | 기준 |
| --- | --- |
| 공통 콘텐츠 최대 폭 | 1,440px |
| 페이지 좌우 여백 | 데스크톱 24px, 901px 이하 20px, 760px 이하 16px |
| 리스트·상세 간격 | 데스크톱 20px, 760px 이하 16px |
| 상세 패널 안쪽 여백 | 데스크톱·태블릿 20px, 760px 이하 18px |
| 리스트 패널 안쪽 여백 | 12px |
| 기본 폼 필드 간격 | 12px; 라벨과 입력 사이 6px; 특수 패턴은 여백 토큰에 맞게 조정 |
| 카드 안쪽 여백 | 공통 카드 17px, 좁은 화면 16px; 워크스페이스 상세 패널은 별도 기준 적용 |

## 2. Controls and interaction

일반 버튼·한 줄 입력·선택 상자는 데스크톱에서 최소 높이 36px, 900px 이하 레이아웃에서 최소 44px다. 컨트롤은 좌우 10px 패딩과 9px 반경을 사용한다. 좁은 화면에서는 텍스트가 잘리지 않도록 줄바꿈하거나 컨트롤을 다음 줄로 보낸다. 여러 줄 입력, 체크박스, 라디오와 캘린더 이벤트 칩은 용도별 크기를 유지한다.

아이콘 전용 동작은 데스크톱 32×32px, 좁은 화면 44×44px 터치 영역을 기준으로 접근 가능한 이름과 툴팁을 제공한다. 워크스페이스 레일은 44px 열 안에서 데스크톱 36×36px 버튼, 좁은 화면 40×44px 버튼을 사용한다. 리사이즈 핸들은 14px 시각 크기와 24px 포인터 영역을 둔다.

포커스는 항상 보이게 한다. 기본 키보드 포커스는 2px 잉크색 외곽선과 4px 오프셋을 쓴다. 워크스페이스 목록 선택 컨트롤은 파란색 2px 외곽선과 2px 오프셋을 사용한다. 선택 상태는 보조 표면 배경과 왼쪽 3px 표시를 함께 쓴다. 로딩·비활성 상태를 색상 하나로만 나타내지 않는다.

한 맥락에는 눈에 띄는 주요 동작을 하나 둔다. 단순하고 자주 쓰는 기능은 버튼, 토글, 직접 입력, 드래그로 제공한다. 폼은 필수 항목부터 보여주며 고급 항목은 ‘세부 정보 추가’ 같은 명시적인 펼치기 안에 둔다. 파괴적 동작은 동작 대상과 결과를 확인할 수 있게 한다. 저장 실패 시 입력한 내용을 보존하고 재시도를 제공한다.

## 3. Navigation and responsive shell

데스크톱 앱은 왼쪽에 워크스페이스 레일과 보조 사이드바를 두고, 콘텐츠 상단에 고정 헤더를 둔다. 레일은 44px, 프로젝트 사이드바는 208px이며, 사이드바 항목은 최소 43px 높이와 10px 가로 여백을 사용한다. 워크스페이스 전환은 아이콘 레일에서, 해당 워크스페이스 내부 항목은 옆 사이드바에서 찾는다. Settings는 레일 하단에 놓는다.

프로젝트 내부의 홈, 일정, 할 일, 문서, 멤버, 설정은 상단 헤더 바로 아래 가로 탭으로 이동한다. 현재 탭은 밑줄과 전경색으로 표시한다. 제목은 한 화면에서 한 번만 표시하고 탭에 제목을 반복하지 않는다. 현재 페이지 제목과 그 페이지에서 자주 쓰는 주요 동작은 같은 행에 정렬한다.

좁은 화면에서 좌측 내비게이션은 닫을 수 있는 드로어로 전환하고 레일은 유지한다. 탭은 글자를 줄이는 대신 가로 스크롤한다. 좌우 여백은 760px 이하에서 16px이다. 리스트·상세 화면은 760px 이하에서 한 열로 바뀐다. 모바일은 한 손 사용을 고려해 터치 목표를 키우고, 촬영 모드에는 현재 할 일과 다음 할 일을 우선 표시한다.

## 4. Icons and visual assets

아이콘은 현재 24×24 viewBox의 자체 SVG 렌더러를 통해 제공한다. 일반 UI 아이콘은 대체로 22px, 레일 아이콘은 20px, 프로젝트 탭 아이콘은 15px로 표시한다. 기본 아이콘은 1.7px 둥근 선과 선 끝을 사용하고, 선택 상태나 프로젝트 식별처럼 면이 더 잘 읽히는 맥락에는 채움형 아이콘을 쓴다. 장면 배치도 오브젝트는 공통 24px 채움형 도형과 광학적 무게를 사용한다.

프로젝트 선택기는 617개의 채움형 아이콘을 제공한다. 검색, 분류, 한 번에 48개 결과 보기, 키보드 탐색을 지원한다. 저장된 기존 아이콘 ID는 호환성을 유지한다. 프로젝트/배치 팔레트와 아이콘은 선택 창 안에서 고르고, 검색 중에도 기존 선택 값은 보존한다. 색상 선택에는 보조기기용 이름이 있다.

아이콘 및 시각 리소스의 원본:
- src/design-system/primitives/icons.js: 일반 내비게이션·조작 아이콘과 SVG 렌더러
- src/design-system/primitives/layout-icons.js: 배치도 오브젝트 및 조명 도형
- src/design-system/icons/catalog.js, paths.js, solid-paths.js: 프로젝트 아이콘 이름·분류·선/채움 경로
- src/design-system/icons/editor-paths.js: 같은 Tabler 3.34.1 아이콘팩의 문서 편집용 선형 아이콘 추가분; 공통 렌더러에서 사용
- src/design-system/icons/TABLER-LICENSE.txt: Tabler 라이선스
- src/design-system/icons/SIMPLE-ICONS-LICENSE.txt: Simple Icons 라이선스
- src/domain/colors.js 및 src/styles.css: 아이덴티티 색상 이름과 값
- src/rotation-cursor.svg: 회전 조작 커서
- 로고와 브랜드 표시는 별도 이미지 파일이 아닌 텍스트 및 SVG 컴포넌트로 구성된다.

프로젝트 아이콘 원본은 Tabler Icons 3.34.1(MIT), KakaoTalk 아이콘은 Simple Icons 15.19.0(CC0)에서 가져온다. 라이선스 파일을 함께 유지하고 업스트림 업데이트 시 버전을 검토한다. 인터페이스 설명용 그래픽과 앱 내 조작 아이콘은 목적이 다르므로 혼용하지 않는다.

## 5. Component architecture and source of truth

스타일은 **tokens → primitives → patterns → features → pages** 순서로 조립한다. 공통 버튼, 아이콘, 색상 선택기, 내비게이션, 리스트·상세 패턴을 페이지마다 다시 만들거나 임의로 덮어쓰지 않는다. 전역 스타일은 공통 토큰과 컴포넌트에서 한 번 정의한다. 브라우저 기본 동작을 유지해야 하는 컨트롤은 충분한 이유 없이 모양을 재정의하지 않는다.

| 역할 | 구현 위치 |
| --- | --- |
| 기본 색상·타입·반경·컨트롤·반응형 토큰과 기반 컴포넌트 | src/styles.css |
| 워크스페이스 공통 프레임, 제목 행, 리스트·상세 레이아웃 | src/workspaces.css |
| 대여소 갤러리·상세 편집 | src/features/rental-vendors.js, src/workspaces.css |
| 앱 내비게이션과 프로젝트 탭 | src/patterns/navigation.js |
| 공통 앱 셸·헤더 | src/app/shell.js |
| 아이콘 렌더링·카탈로그·색상 선택기 | src/design-system/ |
| Studio의 용어 치환 | src/ui-vocabulary.js |
| 이 UI 언어 문서 | docs/UI_LANGUAGE.md |
| 관련 보조 기준 | docs/UI_CONTROL_STANDARDS.md, docs/PROJECT_ICONS.md, docs/QA_UI.md, docs/QA_LAYOUT.md |

src/workspaces.css는 기능별 스타일 뒤에 로드되며 공통 워크스페이스 프레임을 소유한다. 새 공통 디자인 기준을 추가할 때 문서에만 토큰을 제안하지 말고 실제 구현의 출처도 함께 정한다. 이 문서는 디자인 기준이며 런타임 테마 파일이나 별도 디자인 토큰 패키지를 대신하지 않는다.

## 6. Studio product patterns

### Home workspace
홈 워크스페이스는 전역 레일의 첫 번째 항목으로 둔다. 날짜·개인 인사말·소개 문구 없이 프로젝트 수·가까운 촬영·미완료 할 일 요약부터 보여주는 시작 대시보드를 제공한다. 헤더에는 개인 문서와 프로젝트 추가 바로가기를 둔다. 프로젝트를 고르면 기존 프로젝트 홈으로 이동한다. 요약은 프로젝트 데이터의 읽기 전용 집계이며, 개인 문서는 기존 계정별 문서 저장소와 문서 브라우저를 사용한다. 화면은 공통 카드·타입·간격 토큰을 따르고, 좁은 화면에서는 한 열로 쌓는다.

### Production and references
화면의 우선순위는 현재 상태와 다음 행동, 제작 핵심 정보, 보조 설명, 관리 정보 순이다. 촬영·대본·카메라·레퍼런스·사람·장비를 관련 화면에서 바로 확인하며, 항목에서 연결 자료를 열어도 해당 촬영 맥락을 보존한다. 레퍼런스는 표보다 이미지 보드/그리드, 큰 미리보기, 그룹 이름과 가벼운 태그를 우선한다.

### Materials workspace

자료 워크스페이스는 **모든 자료**를 원본 저장소로 사용하고 레퍼런스는 그 자료를 묶어 쓰는 보드로 제공한다. 모든 자료 안에서는 전체 / 사진 / 영상 / 문서 / 기타 파일 / 링크 탭으로 유형을 나눈다. 이미지와 영상은 Pinterest처럼 카드 높이를 콘텐츠 비율에 맞춘 갤러리로 훑고, 카드를 열면 파일 하나를 크게 확인한다. 문서와 일반 파일은 유형 아이콘·이름·미리보기 또는 파일 정보를 표시한다. 공통 카드·간격·색상 토큰을 사용하고 장식보다 자료 식별과 빠른 탐색을 우선한다.

자료는 제목, 분류, 태그, 업로드 날짜를 검색·필터링할 수 있고 업로드 날짜순으로 정렬할 수 있다. 업로드 날짜는 시스템이 기록한다. 이전 자료에 날짜를 확인할 수 없으면 임의 날짜를 만들지 않는다. 링크도 자료로 등록하며 가능한 경우 페이지 제목·대표 이미지·설명을 카드 미리보기에 표시하고, 미리보기 정보가 없으면 링크와 입력한 제목을 보여준다.

모든 자료에서 올린 파일을 레퍼런스에 연결할 수 있고, 레퍼런스 안에서 올린 파일도 모든 자료에 원본으로 등록한다. 레퍼런스에는 파일을 복제하지 않고 원본 자료를 연결한다. 보드에서 연결을 해제해도 원본은 유지하며, 원본 삭제는 별도 동작으로 확인한다. 문서 자료는 문서 유형 탭에서 찾고 기존 블록 편집기, 자동 저장, 개인/프로젝트 저장 위치와 문서별 주소를 유지한다.

### Shoot Mode
촬영 모드는 한 손 모바일 사용을 위해 큰 터치 목표, NOW/NEXT 계층, 최소한의 주변 UI, 현재 담당 정보, 대본·레퍼런스로 가는 한 번의 동작을 우선한다. 촬영에 영향을 주지 않는 관리 메타데이터는 숨긴다. 검증 질문: 현장에서 휴대전화를 든 사용자가 3초 안에 다음 행동을 파악할 수 있는가?

### Documents in Materials

문서 브라우저는 별도 워크스페이스가 아니라 자료 워크스페이스의 문서 유형에서 연다. 전체 자료 갤러리에서도 문서를 찾을 수 있으며, 문서 전용 탭은 전체 / 내 문서 / 프로젝트 문서를 제공한다. 제목·본문 검색, 프로젝트 필터, 이름순·위치순 정렬을 사용한다. 목록에는 문서 이름, 짧은 본문 미리보기, 소속 위치를 표시한다. 검색·필터·추가 동작은 같은 상단 행에 배치하며 공통 워크스페이스 여백과 컨트롤 크기를 따른다.

내 문서는 프로젝트 없이 계정에 저장하고 기존 프로젝트 문서는 원본 위치에서 연다. 문서를 선택하면 동일한 블록 편집기를 사용한다. 내 문서의 ‘문서 목록’ 동작은 저장 후 브라우저로 돌아가며 저장 실패 시 편집 내용을 유지한다. 문서별 주소는 document 쿼리로 선택을 유지한다. 프로젝트 자료와 개인 문서의 저장 버전은 분리하고 계정 간 문서는 공개하지 않는다. 레퍼런스 블록은 기존 자료 워크스페이스의 레퍼런스를 연결한다.

구현은 src/features/document-workspace.js(브라우저), src/features/documents.js(공통 편집기), server/document-library.js(계정별 문서 저장)를 사용한다.

### Scripture workspace

말씀은 레일의 책 아이콘으로 여는 독립 워크스페이스이며 사이드바에 말씀 노트 / QT / 성경을 둔다. 말씀 노트와 QT의 문서 원본은 기존 블록 편집기와 서식·블록 메뉴·자동 저장·터치 이동 지연을 사용한다. 말씀 노트의 분류·날짜·성경 본문·설교자는 본문 위의 공통 폼 필드로 표시하고, QT의 기본 작성 화면은 아래의 분할 양식을 사용한다. 노트별 주소에 선택 문서를 유지하고, 중복된 문서 선택기와 새 문서 버튼은 숨긴다. 노트 복제·삭제는 해당 노트에 적용한다. 가져온 노션의 나머지 속성은 펼치기 안에 보존한다.

성경은 가져온 데이터의 책 / 장 선택과 구절·본문 검색을 제공한다. 성경 화면은 장 제목과 이전·다음 장 이동 아래 절 번호와 본문을 연속으로 배치한다. 읽기 폭은 최대 880px, 본문은 --text-section(16px)과 1.95 행간의 명조 계열을 사용하며 주변 조작은 기존 공통 토큰을 유지한다. 선택한 절은 --selected 배경으로 표시하고 키보드 포커스를 제공한다. 장의 경계를 넘으면 이전·다음 책으로 이동하며 성경 처음·끝에서는 해당 이동을 비활성화한다. 검색 결과는 책·장·절 표기를 유지하고, 노트 내부 인용 선택기는 기존의 간결한 목록을 사용한다. 원본 데이터에 없는 소제목이나 병행 본문은 만들어 표시하지 않는다. 선택한 구절은 인용 블록으로 노트에 넣으며 긴 본문은 블록 길이에 맞춰 나눈다. 구절 체크는 새 기록을 만들거나 기존 노트에 추가하기 위한 선택이며 완료 상태를 뜻하지 않는다. 성경은 사용자별 데이터로 저장하고 앱의 공개 자산에 본문을 포함하지 않는다.

노션 ZIP은 가져올 권·구절 또는 노트 수를 먼저 확인하고 가져온다. 성경 CSV의 책·장·절 식별자를 유지하며, 같은 ZIP·노트를 다시 가져와도 중복 생성하거나 수정한 노트를 덮어쓰지 않는다. 말씀 노트와 성경은 계정별로 분리하고 계정 삭제 시 함께 정리한다.

QT 첫 화면은 지난 기록을 날짜 내림차순 목록으로 표시하고 맨 위에 같은 행 패턴의 ‘오늘 QT 만들기 / 이어쓰기’를 둔다. 매일성경 조회는 만들기를 누를 때 수행하며 목록 조회와 기존 기록 열기는 공급자 접속 없이 동작한다. 한국 시간(Asia/Seoul)으로 날짜를 정하고, 목록에서 날짜를 바꾸어 다른 날을 기록할 수 있다.

QT 작성은 왼쪽 기록 / 오른쪽 성경의 두 열이며 900px 이하에서는 같은 순서로 한 열이 된다. 왼쪽에는 편집 가능한 제목을 --text-page로 두고 날짜·원문·저장 상태는 보조 상단 행으로 분리한다. 감사 / 나에게 주는 말씀 / 나의 적용 / 기도제목은 --text-section 제목 아래 테두리 없는 문서형 contenteditable 영역으로 배치한다. 빈 영역은 보조색 자리표시자를 보여주고 포커스를 표시한다. 감사·기도제목은 번호 항목을 늘리거나 지울 수 있고 Enter로 다음 항목, Shift+Enter로 줄바꿈한다. ‘기존 QT 기록’ 등 원문 펼치기는 노출하지 않으며 데이터 자체는 보존한다.

기도제목 구역의 ‘오늘 기도 / 기존 기도’ 버튼은 동일한 위치에서 내용을 전환하고 aria-pressed와 선택 배경을 함께 표시한다. 오늘 기도는 나의 기도 / 다른 사람을 위한 기도와 대상 이름을 둔다. 기존 기도는 날짜·대상·내용과 간결한 오늘 추가 버튼을 제공하고 서버 검색·대상 필터·페이지 조회를 사용한다. 기존 항목을 오늘에 추가할 때 원본을 수정하지 않는 참조 복사로 연결한다.

오른쪽 맨 위 성경 구절 제목을 직접 편집하며 별도의 ‘성경 본문’ 라벨·입력란을 중복 배치하지 않는다. 쉼표로 여러 본문을 구분하고 범위를 확인한 뒤 본문을 표시한다. 구절 변경에 실패하면 이전 본문을 보존하고 오류와 Escape 취소를 제공한다. 성경은 기존 장별 읽기의 서체·행간을 사용한다.

성경 텍스트 선택과 우클릭은 기존 document-selection-menu 표면·아이콘·크기와 색상 격자를 공유한다. 기본 서식·글자색·하이라이트·링크와 ‘메모’를 제공하며, 하이라이트와 서식은 해당 QT에만 표시한다. 성경 화면에는 강조 색상을 보이지 않는다. 메모는 사용자/책/장/절/문자 범위를 기준으로 공유하고 노란색 점선 밑줄, 마우스 오버·포커스 오버레이로 표시한다. 범위 텍스트가 바뀐 경우 잘못된 위치에 표시하지 않는다. 메모 오버레이는 --surface/--line/--r-surface/--shadow를 사용하고 편집 창에는 메모·취소·저장을 둔다. 임의 HTML 입력은 허용하지 않으며 키보드 Escape로 메뉴·메모를 닫는다.

QT 본문은 생성 시 스냅샷으로 저장하고 기존 기록을 외부 재조회로 덮어쓰지 않는다. 만들기 실패 시 실제 오류와 재시도·직접 기록을 제공하며 임의 본문은 생성하지 않는다. 자동 저장 실패·버전 충돌 시 입력을 유지하고 화면 이동 전에 저장·재시도를 수행한다. 실제 공급자 접속 검증과 합성 응답 테스트를 구분한다.

구현은 src/features/scripture-workspace.js, src/domain/scripture.js 및 bible.js, server/scripture.js, server/notion-scripture-import.js, server/daily-qt.js를 사용한다. QT 양식은 src/features/qt-editor.js, 안정적인 항목·구절 식별은 src/domain/qt-journal.js, 공용 구절 주석은 src/features/bible-annotations.js와 src/domain/verse-annotations.js, 선택·우클릭 메뉴는 src/features/scripture-selection-menu.js, 저장 대기·재시도·이탈 보호는 src/features/scripture-drafts.js에서 구현한다.

| 아이콘 | 기존 Tabler 3.34.1 선형 아이콘팩, 공통 icon() 렌더러, 블록 메뉴 15px·서식 도구 모음 18px와 1.7px 선; 색상 버튼은 둥근 사각형 안의 A로 표시하고 글자색과 배경색을 현재 선택에 맞춰 표시 |

앱 화면 전역에서 우클릭하면 우클릭 위치에 공통 메뉴를 표시한다. 키보드의 Context Menu 키와 Shift+F10도 지원한다. 입력 중에는 잘라내기·복사·붙여넣기·모두 선택을, 텍스트·링크·이미지 위에서는 가능한 복사 동작을 제공한다. 그 외 화면에서는 새로고침과 화면 위/아래 이동을 제공한다. 문서 블록은 기존 블록 전용 메뉴를 계속 열고, 텍스트 선택 서식 메뉴는 선택 범위에 붙는 별도 도구 모음으로 유지한다.

전역 메뉴와 문서 블록 메뉴는 폭 240px, 패널 안쪽 여백 4px, 선택 행 데스크톱 최소 32px / 900px 이하 최소 36px, --text-body(13px), 프로젝트 탭과 같은 15px 아이콘, --r-surface(14px), --r-control(9px)을 공유한다. 항목은 세로 4px·가로 8px 패딩과 6px 아이콘 간격으로 조밀하게 배치한다. 서식 선택 도구 모음은 폭 240px, 패널 안쪽 여백 4px, 18px 아이콘으로 맞추고 5열 아이콘 격자 간격은 2px로 둔다. 아이콘 동작은 데스크톱 32×32px / 900px 이하 44×44px로 둔다. 색상 격자는 패널 여백 8px, 칸 간격 4px로 줄여 높이를 다듬되 32px 견본과 5×2 배열은 유지한다. A 색상 버튼과 팔레트 선택 상태는 현재 선택 범위의 텍스트 색·배경색을 실시간으로 반영한다. 색상 하위 메뉴도 `document-color-grid`로 열어 텍스트색과 배경색을 각각 5×2 격자로 표시하고, 견본은 32px를 유지한다. 화면 가장자리에서 8px 이상 떨어지게 위치를 보정하고, 높이는 화면에 맞춰 스크롤한다. 흰 표면, 구분선, 얕은 그림자, 회색 호버 배경을 사용하며 Escape와 방향키로 조작한다.

블록 핸들 또는 우클릭으로 작업 메뉴를 연다. 검색, 전환, 색상, 복제, 이동, 삭제와 기존 클립보드·블록 추가·정렬 동작을 유지한다. 전환·색상 하위 메뉴는 옆에 배치하고 화면이 좁으면 반대쪽으로 조정한다. 텍스트 선택 메뉴는 선택한 범위를 유지한 채 서식을 적용하며 색상 격자는 패널 위에 붙인다. 최근 사용 색상은 최대 5개를 현재 실행 중인 편집 세션에서 표시한다. 문서의 텍스트·배경 색상은 콘텐츠 서식이므로 프로젝트 식별용 6색 팔레트와 구분한다.

선택한 블록은 --selected 배경으로, 현재 서식 값은 체크 또는 견본 외곽선으로 표시한다. 방향키·Enter·Escape와 외부 클릭 동작을 유지하고, 키보드 포커스는 공통 2px 잉크색 외곽선·4px 오프셋을 사용한다. 아이콘 전용 동작에는 접근 가능한 이름과 툴팁을 둔다. 제공하지 않는 댓글·반응·편집 제안·수학 공식·AI 동작은 비활성 상태로 표시한다. 메뉴 변경으로 저장 방식, 문서 내용, 레퍼런스 연결이나 터치 드래그 지연을 바꾸지 않는다.

구현 출처는 src/features/document-menus.js(메뉴·아이콘 매핑), src/features/documents.js(편집 동작 연결), src/workspaces.css(메뉴 스타일), src/design-system/primitives/icons.js 및 icons/editor-paths.js(공통 아이콘팩)다.

### Project and workspace settings
프로젝트 설정은 넓은 화면에서 이름 → 색상·아이콘 → 설명을 왼쪽에 두고 촬영일 → 시간 → 장소를 오른쪽에 둔다. 작은 화면에서는 같은 순서로 세로 배치한다. 색상과 아이콘 설정은 라벨을 위쪽에 정렬하며 내부 세로 구분선을 만들지 않는다. 프로젝트 모양 선택에서는 아이콘을 왼쪽, 색상 팔레트를 오른쪽에 둔다.

계정·데이터·외부 앱 연결·관리자 정보는 속성명과 값/동작을 정렬한다. 로그아웃은 계정 설정 하단의 구분선 아래 위험 동작으로 둔다. 공유 프로젝트는 있을 때만 표시하며 불러오기에 실패하면 재시도를 제공한다.

### Equipment and Materials workspaces
자료 워크스페이스는 모든 자료와 레퍼런스를 제공하며, 대여소는 장비 워크스페이스에 둔다. 장비 워크스페이스 사이드바는 멤버 장비 / 조직 장비 / 장비 도감 / 대여소로 구성한다. 대여소는 장비 도감과 같은 카드형 갤러리로 탐색하고, 검색과 추가 동작은 갤러리 상단에 둔다. 카드를 열면 대여소 정보를 기존 폼으로 확인·편집한다. 빈 상태에는 대여소 추가 동작을 제공한다.

조직 장비의 탐색 순서는 **장비 목록 / 반출 신청 / 반출 현황 / 반출·반납 내역 / 조직 관리**다. 조직 선택은 검색 드롭다운으로 제공하며 탭 이동과 새로고침에서도 선택 조직을 유지한다. 멤버 장비에는 반출·반납 기능을 제공하지 않는다.

멤버·조직 장비는 공통 장비 요약, 검색 목록, 선택 항목 상세와 편집 동작을 사용한다. 장비 등록은 버튼에서 입력 창을 연다. 장비 관리 목록은 카메라·렌즈·조명·삼각대·SD 카드·음향·기타 순으로 묶는다. 프로젝트 장비 상태는 ‘사용하기’와 ‘✓ 사용 확정’으로 구별한다. 장비 도감은 제조사·정식 이름·별명·사진을 제공하고 소유자나 재고는 표시하지 않는다. 사진이 없으면 ‘사진 없음’을 표시한다.

### Administration and people
사용자 관리는 가입자 / 조직 / 비가입자 그룹으로 구성한다. 목록에서 항목을 고르면 하나의 편집 화면으로 이동하며 목록 복귀 동작을 제공한다. 멤버 정보의 ‘호칭’과 프로젝트에서 맡는 역할은 구분한다. 프로젝트 역할과 콜타임은 해당 프로젝트의 멤버 항목에서 관리한다. 기존 저장 값을 새 UI 의미로 자동 삭제하거나 다른 필드로 옮기지 않는다.

회원 초대는 관리자 워크스페이스의 별도 메뉴에 둔다. 팀 생성·멤버 초대·팀 배정은 프로젝트의 멤버 탭에서 관리한다. 내부 권한 키 super_admin의 화면 표기는 ‘대표’로 통일한다. 마지막 프로젝트를 지우면 가짜 프로젝트 대신 ‘프로젝트가 없습니다.’와 프로젝트 추가 동작을 보여준다.

## 7. Quality checks

새 화면이나 공통 스타일 변경을 검토할 때 확인한다.

- 3초 안에 현재 상태와 다음 행동을 알 수 있는가?
- 제목·주요 동작·탭의 위치와 위계가 기존 워크스페이스와 같은가?
- 색상 없이도 상태와 선택을 구별할 수 있는가?
- 키보드 포커스, 접근 가능한 이름, 작은 화면의 44px 조작 목표를 제공하는가?
- 760px 이하에서 리스트/상세가 한 열로 바뀌고 탭·텍스트가 잘리지 않는가?
- 같은 역할의 컨트롤이 공통 토큰과 컴포넌트를 사용하는가?
- 새로 쓰거나 수정한 디자인 자산의 출처와 라이선스를 기록했는가?
