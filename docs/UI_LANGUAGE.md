# Studio UI Language

이 문서는 Studio와 같은 제품군 앱이 공유할 시각·상호작용 언어의 기준이다. Studio에만 필요한 정보 구조와 업무 흐름은 제품 패턴으로 구분한다. 새 화면은 공통 토큰과 컴포넌트를 우선 사용하고, 새로운 전역 규칙은 이 문서와 구현을 함께 갱신한다.

Studio의 UI 원칙은 **Glanceable · Calm · Contextual · Connected · Shoot-friendly**다. 화면은 현재 상태와 다음 행동, 핵심 업무 정보, 보조 설명, 관리 메타데이터 순으로 읽힌다. 정보는 풍부하게 보여주되 장식은 업무 판단에 도움이 될 때만 쓴다.

## 1. Visual foundations

### Color

라이트 모드 화면과 대부분의 패널은 흰색 바탕이다. 설정 → 앱 설정의 화면 모드에서 라이트 모드 / 다크 모드를 선택한다. 초기값은 운영체제 테마와 관계없이 다크이며, 선택은 이 브라우저에 저장해 재접속과 다른 탭에서도 유지한다. 다크 모드는 홈뿐 아니라 로그인·프로덕션·장비·자료·말씀·관리자·설정·팝업 전체에 공통 색상 토큰으로 적용한다. `src/theme.js`는 첫 화면이 그려지기 전 선택을 복원하고 `src/theme.css`는 공통 색상 및 기존 고정 색상 표면의 대체값을 소유한다. 배경·표면·구분선·텍스트·상태·포커스를 함께 전환하되 원본 사진, 프로젝트 식별색, 사용자가 문서에 지정한 색은 보존한다. 다크 기본 배경은 #111113, 표면 #19191c, 보조 표면 #232327, 본문 #f0f0ed, 보조 글자 #aaaab2, 구분선 #36363d다. 보조 표면은 차가운 중성 회색을 쓰며, 선택 상태에는 옅은 파랑을 사용한다. 좌측 워크스페이스 레일은 흰색과 구분되는 옅은 회색이다. 색상은 상태, 선택, 프로젝트 식별처럼 의미가 있을 때 사용한다.

| 역할 | CSS 변수 | 현재 값 |
| --- | --- | --- |
| 앱·카드 표면 | --bg, --surface | #fff |
| 보조 표면 | --surface-2 | #f4f5f7 |
| 기본 글자 | --ink | #18181b |
| 강조·주요 동작 | --accent | #2563eb (다크 #8bb8ff) |
| 보조 글자 | --muted | #71717a |
| 구분선 | --line | #e7e7eb |
| 선택 항목 배경 | --selected | #f0f5ff |
| 준비 완료 | --ok | #2f6b48 |
| 확인 필요 | --warn | #8a641d |
| 문제 있음 | --bad | #a13b32 |

프로젝트 및 배치 아이덴티티 색상은 6색 팔레트로 제한한다: 보라 #8858ef, 파랑 #4384ee, 주황 #ff812c, 초록 #2d9b73, 분홍 #df5f94, 회색 #535660. 이 팔레트는 의미가 아니라 식별을 위한 색상이다.

상태는 색만으로 표현하지 않는다. 읽을 수 있는 레이블을 함께 쓰고 필요한 경우 아이콘이나 모양을 보탠다. 기본 상태 어휘는 **준비 완료 / 확인 필요 / 문제 있음 / 미정**이다. 주요 동작은 진한 잉크색 버튼, 보조 동작은 흰색 테두리 버튼, 덜 중요한 동작은 투명 버튼으로 표시한다. 위험한 동작은 명확한 확인 문구와 붉은색 계열로 구별한다.

### Typography

글꼴 스택은 Inter를 우선 사용하고 Apple·BlinkMac·Segoe UI 시스템 글꼴로 대체한다. 별도 폰트 파일은 저장소에 포함되어 있지 않다. 아래 역할 토큰을 기준으로 하며, 작은 화면이라고 탭이나 제목 글자를 임의로 줄이지 않는다. 표의 px 값은 브라우저 기본 글자 크기 16px 기준이다.

| 역할 | CSS 변수 | 크기 | 대표 사용처 |
| --- | --- | --- | --- |
| 페이지 제목·핵심 수치 | --text-page, --text-metric | 22px / 1.375rem | 화면 제목, 준비도와 통계 |
| 섹션 제목 | --text-section | 16px / 1rem | 화면 내 구역 제목 |
| 카드·상단바 제목 | --text-title | 15px / .9375rem | 카드, 프로젝트, 사이드바 제목 |
| 기본 본문·조작 | --text-body | 14.5px / .90625rem | 탭, 버튼, 목록 이름, 라벨 |
| 보조 설명 | --text-support | 12px / .75rem | 설명, 시간, 담당자, 도움말 |
| 메타 정보 | --text-meta | 11px / .6875rem | 상태 배지, 통계 라벨, 저장 상태 |

기본 본문 행간은 1.5, 보조 설명은 1.6, 카드 제목은 약 1.4, 페이지 제목은 약 1.3을 사용한다. 일반 글자 두께는 400, 제목·선택 상태·강조는 500을 기본으로 한다. 글자 크기는 rem 토큰을 사용해 사용자 확대 설정을 존중한다. 모바일의 텍스트 입력은 브라우저 확대 방지를 위해 16px로 표시한다.

화면 문구는 짧고 구체적인 한국어 동사형을 우선한다. 제목이 이미 설명하는 정보를 반복하지 않는다. 권한, 만료, 입력 제한, 저장 실패와 복구처럼 사용자가 다음 행동을 결정하는 정보는 해당 위치에 남긴다.

### Shape, spacing and elevation

모서리는 둥근 사각형을 기본으로 하고 corner-shape: squircle을 지원하는 브라우저에서는 연속 곡률을 적용한다. 구현은 항상 border-radius 대체값을 먼저 제공한다. 실제 공통 반경 토큰은 --r-control 9px, --r-surface 14px, --r-panel 20px다. 배지처럼 원형이 의미를 갖는 요소와 캔버스 오브젝트는 해당 패턴의 형상을 유지한다. 별도의 --r-hero 같은 토큰은 현재 없다.

공통 여백 토큰은 4px 단위의 4, 8, 12, 16, 20, 24, 32px이다. 페이지별 배치가 이를 무시해야 한다면 기존 패턴의 예외인지 확인하고 예외를 국소화한다. 기본 표면은 1px 구분선과 매우 옅은 그림자를 사용한다. 모달은 표면보다 강한 그림자와 반투명 오버레이로 전후 관계를 분명히 한다.

| 용도 | 기준 |
| --- | --- |
| 공통 콘텐츠 최대 폭 | 가용 폭 전체; 문서·성경 읽기 표면만 별도 최대 폭 |
| 페이지 좌우 여백 | 데스크톱 24px, 모바일 360px 이상 28px / 그 미만 24px |
| 리스트·상세 간격 | 데스크톱 20px, 760px 이하 16px |
| 상세 패널 안쪽 여백 | 데스크톱·태블릿 20px, 760px 이하 18px |
| 리스트 패널 안쪽 여백 | 12px |
| 기본 폼 필드 간격 | 12px; 라벨과 입력 사이 6px; 특수 패턴은 여백 토큰에 맞게 조정 |
| 카드 안쪽 여백 | 공통 카드 17px, 좁은 화면 16px; 워크스페이스 상세 패널은 별도 기준 적용 |

## 2. Controls and interaction

일반 버튼·한 줄 입력·선택 상자는 데스크톱에서 최소 높이 36px, 900px 이하 레이아웃에서 최소 44px다. 컨트롤은 좌우 10px 패딩과 9px 반경을 사용한다. 좁은 화면에서는 텍스트가 잘리지 않도록 줄바꿈하거나 컨트롤을 다음 줄로 보낸다. 여러 줄 입력, 체크박스, 라디오와 캘린더 이벤트 칩은 용도별 크기를 유지한다.

아이콘 전용 동작은 데스크톱 36×36px, 좁은 화면 44×44px 터치 영역을 기준으로 접근 가능한 이름과 툴팁을 제공한다. 문서 메뉴·실행 취소·다시 실행의 공통 툴팁은 hover와 키보드 포커스에서 표시하고 aria-describedby로 연결하며 Escape·포커스 이탈·화면 제거 시 정리한다. 데스크톱 워크스페이스 레일은 54px 열 안에 38×38px 버튼과 22px 아이콘을 사용한다. 리사이즈 핸들은 14px 시각 크기와 24px 포인터 영역을 둔다.

포커스는 항상 보이게 한다. 기본 키보드 포커스는 2px 잉크색 외곽선과 4px 오프셋을 쓴다. 워크스페이스 목록 선택 컨트롤은 파란색 2px 외곽선과 2px 오프셋을 사용한다. 선택 상태는 보조 표면 배경과 왼쪽 3px 표시를 함께 쓴다. 로딩·비활성 상태를 색상 하나로만 나타내지 않는다.

한 맥락에는 눈에 띄는 주요 동작을 하나 둔다. 단순하고 자주 쓰는 기능은 버튼, 토글, 직접 입력, 드래그로 제공한다. 폼은 필수 항목부터 보여주며 고급 항목은 ‘세부 정보 추가’ 같은 명시적인 펼치기 안에 둔다. 파괴적 동작은 동작 대상과 결과를 확인할 수 있게 한다. 저장 실패 시 입력한 내용을 보존하고 재시도를 제공한다.

## 3. Navigation and responsive shell

데스크톱 앱은 왼쪽에 워크스페이스 레일과 보조 사이드바를 두고, 콘텐츠 상단에 고정 헤더를 둔다. 레일은 데스크톱 54px(38px 버튼과 좌우 8px 여백, 항목 간 14px), 프로젝트 사이드바는 208px이며, 사이드바 항목은 최소 36px 높이를 사용한다. 학기 토글 행은 38px, 2단 사이드바는 위아래 16px 반경과 제목 상단·좌측 20px 여백, 옅은 왼쪽 그림자를 사용한다. 워크스페이스 전환은 아이콘 레일에서, 해당 워크스페이스 내부 항목은 옆 사이드바에서 찾는다. Settings는 레일 하단에 놓는다.

프로젝트 내부의 홈, 일정, 할 일, 문서, 멤버, 설정은 상단 헤더 바로 아래 가로 탭으로 이동한다. 현재 탭은 밑줄과 전경색으로 표시한다. 제목은 한 화면에서 한 번만 표시하고 탭에 제목을 반복하지 않는다. 현재 페이지 제목과 그 페이지에서 자주 쓰는 주요 동작은 같은 행에 정렬한다.

900px 이하에서는 1단 워크스페이스 메뉴를 좌우·바닥에서 띄운 플로팅 하단바로 전환한다. 2단 메뉴는 전체 화면 목록으로 표시하고 항목을 고르면 기존 콘텐츠 화면을 연다. 비프로젝트 워크스페이스를 선택하면 아이콘 전용 하위 탭을 즉시 표시한다. 프로젝트는 먼저 기존 프로젝트 목록을 열고 선택 후 프로젝트 탭을 표시한다. 설정 하위 바의 관리자 방패 버튼은 권한이 있는 관리자 항목만 모은 모바일 목록을 연다. 데스크톱에서는 데이터 아래 구분선 뒤의 기존 순서를 유지한다. 모바일 하단은 워크스페이스 선택과 하위 탭의 두 단계로 표시한다. 하위 탭 pill 왼쪽에 같은 높이의 독립 원형 뒤로가기를 두어 홈 대시보드와 기본 워크스페이스 바로 이동하며 브라우저 뒤로·앞으로도 단계와 목록 상태를 복구한다. 헤더에는 별도의 중복 뒤로가기를 추가하지 않는다. 목록 열기·닫기는 편집기 DOM과 URL을 보존하고 목록 상태는 브라우저 이력으로 구분한다. 하단바는 iPhone 안전 영역과 최소 44px 터치 영역을 적용하고 콘텐츠 하단 여백을 확보한다. 좁은 화면의 많은 메뉴는 하단바 안에서 가로로 스크롤하며 현재 메뉴가 보이도록 한다. 소프트 키보드나 모달이 열린 동안은 바를 숨기고 포커스 대상에서 제외한다. 데스크톱 사이드바는 유지한다. 탭은 글자를 줄이는 대신 가로 스크롤한다. 좌우 여백은 모바일 360px 이상 28px, 그 미만 24px이며 중첩 컨테이너에 중복 적용하지 않는다. 리스트·상세 화면은 760px 이하에서 한 열로 바뀐다. 모바일은 한 손 사용을 고려해 터치 목표를 키우고, 촬영 모드에는 현재 할 일과 다음 할 일을 우선 표시한다.

## 4. Icons and visual assets

공통 UI와 내비게이션 아이콘은 Ionicons 8.0.13의 `outline`과 `filled` SVG 쌍을 공통 렌더러로 제공한다. Ionicons 원본의 512×512 viewBox를 유지하며 일반 동작 아이콘은 18px, 레일 아이콘은 22px, 프로젝트 탭 아이콘은 15px로 표시한다. `sharp` 변형은 사용하지 않는다. 장면 배치도와 조명 오브젝트도 Ionicons 8.0.13 자산을 사용하고 화면에서는 기존 24px 크기에 맞춰 표시한다.

프로젝트 선택기는 617개의 채움형 아이콘을 제공한다. 검색, 분류, 한 번에 48개 결과 보기, 키보드 탐색을 지원한다. 저장된 기존 아이콘 ID는 호환성을 유지한다. 프로젝트/배치 팔레트와 아이콘은 선택 창 안에서 고르고, 검색 중에도 기존 선택 값은 보존한다. 색상 선택에는 보조기기용 이름이 있다.

홈 레일은 굴뚝 없는 집, 자료 레일은 살짝 기울어 겹친 문서 두 장을 사용한다. 참고 이미지에 맞춘 Studio 전용 도형을 `src/design-system/icons/workspace-icons.js`에 outline/filled 쌍으로 등록하고 공통 512px 렌더러로 표시한다. 말씀 레일은 가로대를 위쪽에 두고 아래 세로대를 길게 뻗은 라틴 십자가를 사용한다. 선형과 채움형은 같은 비율과 윤곽을 공유한다. 말씀 사이드바 기본 순서는 성경 / 구분선 / QT / 말씀 노트 / 구분선 / 감사 / 기도제목이다. 새 순서는 이전 정렬 저장값과 분리하고 이후에도 메뉴 순서는 고정한다. 구분선은 첫 항목 뒤와 세 번째 항목 뒤에 두며 정렬 대상에 포함하지 않는다. 선택 상태·크기·접근성 이름·이동 동작은 기존 레일 규칙을 유지한다.

아이콘 및 시각 리소스의 원본:
- src/design-system/primitives/icons.js 및 src/design-system/icons/ionicons.js: Ionicons 8.0.13 내비게이션·일반 UI 아이콘의 outline/filled 쌍과 SVG 렌더러

## 5. Component architecture and source of truth

스타일은 **tokens → primitives → patterns → features → pages** 역할로 조립한다. 실제 로딩 순서는 `index.html`을 따른다. 기능 CSS 다음의 `theme.css`가 테마를, `controls.css`가 공통 조작 치수·상태를, `document-display.css`가 본문과 문서 배율을 최종 적용한다. `workspaces.css`는 프레임·읽기 폭·워크스페이스 배치를 소유한다. 역할별 토큰을 우선 사용하며 과거 기반 CSS 수치를 최신 기준으로 해석하지 않는다. 문서 간 설명이 충돌하면 덧붙이기보다 해당 표·규칙을 함께 수정한다. 공통 버튼, 아이콘, 색상 선택기, 내비게이션, 리스트·상세 패턴을 페이지마다 다시 만들거나 임의로 덮어쓰지 않는다. 전역 스타일은 공통 토큰과 컴포넌트에서 한 번 정의한다. 브라우저 기본 동작을 유지해야 하는 컨트롤은 충분한 이유 없이 모양을 재정의하지 않는다.

## 6. Studio product patterns

### Home workspace
홈 워크스페이스는 전역 레일의 첫 번째 항목이다. 대시보드는 참고 이미지의 콘솔형 정보 구조를 유지하며 기본 다크 모드에서는 짙은 차콜 표면과 밝은 파란 강조색(#8bb8ff)을 사용한다. 전역 라이트 모드를 선택하면 흰 표면과 파란 강조색(#2563eb)을 사용한다. 상단 중앙에는 JONGYOU STUDIO 워드마크(보조 슬로건 없음), 그 아래에는 프로젝트 이름·촬영 수·미완료 할 일·실제 할 일 완료 비율을 표시하는 전체 폭 목록을 둔다. 다음 패널에는 프로젝트·7일 촬영·미완료·완료 수치와 작업 내용을 모은다. 하단은 제작 / 자료 / 개인 기록 바로가기로 나누며 모두 기존 화면으로 연결한다. 숫자와 상태는 계정의 실제 데이터에서 계산하고 임의 활동이나 상태를 만들지 않는다. 공통 글자 크기·컨트롤 높이·페이지 여백은 유지하고 다른 워크스페이스로 이동해도 선택한 전역 테마를 유지한다. 첫 행 왼쪽에는 가까운 촬영, 오른쪽에는 오늘 QT를 배치한다. 오늘 QT 영역에서 성경 구절 주소와 오늘의 감사를 표시한다. 본문 전문은 표시하지 않는다. 감사는 QT 편집기와 같은 번호·테두리 없는 편집 영역·추가·삭제·Enter 동작과 자동 저장을 공유한다. 아직 QT가 없으면 점선 테두리의 오늘 QT 만들기를 표시한다. 내 문서·프로젝트 추가 바로가기와 개인 작업 공간 카드는 두지 않으며 홈 보조 사이드바에는 대시보드 / 일정 / 할 일을 둔다. 프로젝트 목록은 작업 패널 위에, 남은 할 일은 촬영·QT 아래에 둔다. 대시보드에는 Google Calendar·Tasks 연결 카드를 두지 않는다. 일정에는 프로젝트 일정과 개인 Google Calendar 조회를, 할 일에는 프로젝트별 완료 상태와 Google Tasks 연결 항목을 표시한다. 항목은 해당 프로젝트의 일정·할 일로 연결하고 Google 연결 관리는 설정에서 유지한다. 작은 화면에서는 본문과 감사를 한 열로 쌓는다. 감사 저장 실패 시 입력을 보존한다.

구현은 src/features/home-workspace.js(대시보드), src/features/home-qt.js(QT 조회·감사 추가), src/workspaces.css(배치)를 사용한다.

### Production and references
화면의 우선순위는 현재 상태와 다음 행동, 제작 핵심 정보, 보조 설명, 관리 정보 순이다. 촬영·대본·카메라·레퍼런스·사람·장비를 관련 화면에서 바로 확인하며, 항목에서 연결 자료를 열어도 해당 촬영 맥락을 보존한다. 레퍼런스는 표보다 이미지 보드/그리드, 큰 미리보기, 그룹 이름과 가벼운 태그를 우선한다. 레퍼런스 상세 보드는 사진·영상·문서·파일·링크와 설명 텍스트 블록을 한 캔버스에 함께 배치한다. 항목은 12열 그리드에 맞춰 드래그 또는 방향 버튼으로 이동하고, 작은/보통/큰 크기로 조정하며, 자동 정렬을 제공한다. 텍스트 블록은 제목과 설명을 편집하고 보드에서 제거할 수 있다. 배치는 레퍼런스별로 저장하며, 보드에는 원본 파일을 복사하지 않고 자료 저장소의 ID/URL만 연결한다.

### Materials workspace

자료 워크스페이스는 **모든 자료**를 원본 저장소로 사용하고 레퍼런스는 그 자료를 묶어 쓰는 보드로 제공한다. 모든 자료 안에서는 전체 / 사진 / 영상 / 문서 / 기타 파일 / 링크 탭으로 유형을 나눈다. 이미지와 영상은 Pinterest처럼 카드 높이를 콘텐츠 비율에 맞춘 갤러리로 훑고, 카드를 열면 파일 하나를 크게 확인한다. 문서와 일반 파일은 유형 아이콘·이름·미리보기 또는 파일 정보를 표시한다. 공통 카드·간격·색상 토큰을 사용하고 장식보다 자료 식별과 빠른 탐색을 우선한다.

자료는 제목, 분류, 태그, 업로드 날짜를 검색·필터링할 수 있고 업로드 날짜순으로 정렬할 수 있다. 업로드 날짜는 시스템이 기록하며 문서는 개인 저장 공간과 프로젝트 안의 문서를 함께 보여준다. 이전 자료에서 날짜를 확인할 수 없으면 임의 날짜를 만들지 않는다. 링크도 자료로 등록하며 가능한 경우 페이지 제목·대표 이미지·설명을 카드 미리보기에 표시하고, 미리보기 정보가 없으면 링크와 입력한 제목을 보여준다. 외부 미리보기 이미지는 같은 출처의 제한된 이미지 경로로 제공하고, 미리보기를 가져오지 못하면 링크와 제목으로 대체한다.

모든 자료에서 올린 파일을 레퍼런스에 연결할 수 있고, 레퍼런스 안에서 올린 파일도 모든 자료에 원본으로 등록한다. 레퍼런스에는 파일을 복제하지 않고 원본 자료를 연결한다. 보드에서 연결을 해제해도 원본은 유지하며, 원본 삭제는 별도 동작으로 확인한다. 문서 자료는 문서 유형 탭에서 찾고 기존 블록 편집기, 자동 저장, 개인/프로젝트 저장 위치와 문서별 주소를 유지한다.

### Shoot Mode
촬영 모드는 한 손 모바일 사용을 위해 큰 터치 목표, NOW/NEXT 계층, 최소한의 주변 UI, 현재 담당 정보, 대본·레퍼런스로 가는 한 번의 동작을 우선한다. 촬영에 영향을 주지 않는 관리 메타데이터는 숨긴다. 검증 질문: 현장에서 휴대전화를 든 사용자가 3초 안에 다음 행동을 파악할 수 있는가?

### Documents in Materials

문서 브라우저는 별도 워크스페이스가 아니라 자료 워크스페이스의 문서 유형에서 연다. 전체 자료 갤러리에서도 문서를 찾을 수 있으며, 문서 전용 탭은 전체 / 내 문서 / 프로젝트 문서를 제공한다. 제목·본문 검색, 프로젝트 필터, 이름순·위치순 정렬을 사용한다. 목록에는 문서 이름, 짧은 본문 미리보기, 소속 위치를 표시한다. 검색·필터·추가 동작은 같은 상단 행에 배치하며 공통 워크스페이스 여백과 컨트롤 크기를 따른다.

내 문서는 프로젝트 없이 계정에 저장하고 기존 프로젝트 문서는 원본 위치에서 연다. 문서를 선택하면 동일한 블록 편집기를 사용한다. 내 문서의 ‘문서 목록’ 동작은 저장 후 브라우저로 돌아가며 저장 실패 시 편집 내용을 유지한다. 문서별 주소는 document 쿼리로 선택을 유지한다. 프로젝트 자료와 개인 문서의 저장 버전은 분리하고 계정 간 문서는 공개하지 않는다. 레퍼런스 블록은 기존 자료 워크스페이스의 레퍼런스를 연결한다.

구현은 src/features/document-workspace.js(브라우저), src/features/documents.js(공통 편집기), server/document-library.js(계정별 문서 저장)를 사용한다.

### App-wide context menu

앱 UI(#app)에서 모든 우클릭은 우클릭 위치에 메뉴를 연다. Context Menu 키와 Shift+F10 키도 같은 메뉴를 연다. 입력란에서는 가능한 잘라내기·복사·붙여넣기·모두 선택을 제공하고, 텍스트 선택·링크·이미지에서는 관련 복사 동작을 제공한다. 그 밖의 화면에는 새로고침과 화면 위/아래 이동을 둔다. 문서 블록은 기존 블록 전용 우클릭 메뉴를 유지하고, 텍스트 선택 서식 메뉴도 선택 범위에 붙는 기존 도구 모음으로 유지한다.

전역 메뉴의 크기와 스타일은 기존 문서 블록 메뉴에 맞춘다.

| 글자·아이콘 | --text-body(14.5px), 400 두께; 동작 아이콘 18px(프로젝트 탭은 별도 15px) |

| 키보드 | 포커스 외곽선을 표시하고 위/아래 방향키, Home/End, Enter, Escape를 지원 |

전역 메뉴 구현은 src/features/app-context-menu.js, 연결 지점은 src/app.js, 메뉴 스타일은 src/workspaces.css다. 문서 블록·서식 메뉴도 이 파일의 공통 표면·타입·행 크기를 공유한다.

### Scripture workspace

말씀은 레일의 책 아이콘으로 여는 독립 워크스페이스이며 사이드바에 말씀 노트 / QT / 성경 / 감사 / 기도제목을 둔다. 말씀 노트와 QT의 문서 원본은 기존 블록 편집기와 서식·블록 메뉴·자동 저장·터치 이동 지연을 사용한다. 말씀 노트의 분류·날짜·성경 본문·설교자는 본문 위의 공통 폼 필드로 표시하고, QT의 기본 작성 화면은 아래의 분할 양식을 사용한다. 노트별 주소에 선택 문서를 유지하고, 중복된 문서 선택기와 새 문서 버튼은 숨긴다. 노트 복제·삭제는 해당 노트에 적용한다. 가져온 노션의 나머지 속성은 펼치기 안에 보존한다.

성경은 가져온 데이터의 책 / 장 선택과 구절·본문 검색을 제공한다. 성경 화면은 장 제목과 이전·다음 장 이동 아래 절 번호와 본문을 연속으로 배치한다. 읽기 폭은 문서의 `--document-reading-width`(A4 210mm에서 좌우 20mm와 경계 2px를 뺀 내부 폭)를 공유하며 가용 폭에 맞게 줄어든다. 두 번역은 같은 최대 폭을 가진 동등한 열이고 모바일은 절별 대조 표시를 유지한다. 본문은 --text-section(16px)과 1.95 행간의 명조 계열을 사용하며 주변 조작은 기존 공통 토큰을 유지한다. 선택한 절은 --selected 배경으로 표시하고 키보드 포커스를 제공한다. 장의 경계를 넘으면 이전·다음 책으로 이동하며 성경 처음·끝에서는 해당 이동을 비활성화한다. 검색 결과는 책·장·절 표기를 유지하고, 노트 내부 인용 선택기는 기존의 간결한 목록을 사용한다. 원본 데이터에 없는 소제목이나 병행 본문은 만들어 표시하지 않는다. 선택한 구절은 인용 블록으로 노트에 넣으며 긴 본문은 블록 길이에 맞춰 나눈다. 구절 체크는 새 기록을 만들거나 기존 노트에 추가하기 위한 선택이며 완료 상태를 뜻하지 않는다. 성경은 사용자별 데이터로 저장하고 앱의 공개 자산에 본문을 포함하지 않는다.

노션 ZIP은 가져올 권·구절 또는 노트 수를 먼저 확인하고 가져온다. 성경 CSV의 책·장·절 식별자를 유지하며, 같은 ZIP·노트를 다시 가져와도 중복 생성하거나 수정한 노트를 덮어쓰지 않는다. 말씀 노트와 성경은 계정별로 분리하고 계정 삭제 시 함께 정리한다.

QT 첫 화면은 지난 기록을 날짜 내림차순 목록으로 표시하고 맨 위에 같은 행 패턴의 ‘오늘 QT 만들기 / 이어쓰기’를 둔다. 매일성경 조회는 만들기를 누를 때 수행하며 목록 조회와 기존 기록 열기는 공급자 접속 없이 동작한다. 한국 시간(Asia/Seoul)으로 날짜를 정하고, 목록에서 날짜를 바꾸어 다른 날을 기록할 수 있다.

QT 작성은 왼쪽 기록 / 오른쪽 성경의 두 열이며 900px 이하에서는 같은 순서로 한 열이 된다. 왼쪽에는 편집 가능한 제목을 --text-page로 두고 날짜·원문·저장 상태는 보조 상단 행으로 분리한다. 같은 상단 행의 오른쪽 끝에 성경 본문 숨기기/보이기 아이콘 버튼을 두고 aria-expanded·aria-controls·접근 가능한 이름과 툴팁을 제공한다. 성경을 숨기면 작성 영역을 한 열로 표시하며 입력·주석 데이터는 유지한다. 감사 / 나에게 주는 말씀 / 나의 적용 / 기도제목은 --text-section 제목 아래 테두리 없는 문서형 contenteditable 영역으로 배치한다. 빈 영역은 보조색 자리표시자를 보여주고 포커스를 표시한다. 감사·기도제목은 번호 항목을 늘리거나 지울 수 있고 Enter로 다음 항목, Shift+Enter로 줄바꿈한다. ‘기존 QT 기록’ 등 원문 펼치기는 노출하지 않으며 데이터 자체는 보존한다.

기도제목 구역의 ‘오늘 기도 / 전체 기도제목’ 버튼은 동일한 위치에서 내용을 전환하고 aria-pressed와 선택 배경을 함께 표시한다. 오늘 기도는 나의 기도 / 다른 사람을 위한 기도와 대상 이름을 둔다. 기존 기도는 날짜·대상·내용과 간결한 오늘 추가 버튼을 제공하고 서버 검색·대상 필터·페이지 조회를 사용한다. 기존 항목을 오늘에 추가할 때 원본을 수정하지 않는 참조 복사로 연결한다.

오른쪽 맨 위 성경 구절 제목을 직접 편집하며 별도의 ‘성경 본문’ 라벨·입력란을 중복 배치하지 않는다. 쉼표로 여러 본문을 구분하고 범위를 확인한 뒤 본문을 표시한다. 구절 변경에 실패하면 이전 본문을 보존하고 오류와 Escape 취소를 제공한다. 성경은 기존 장별 읽기의 서체·행간을 사용한다.

성경 텍스트 선택과 우클릭은 기존 document-selection-menu 표면·아이콘·크기와 색상 격자를 공유한다. 상단 첫 행은 아이콘과 ‘복사’ 동작을 표시하고, 색상·굵게·기울임·밑줄의 4열 한 행과 하단 ‘메모’를 제공한다. 서식 지우기·더 보기·링크·취소선·코드는 표시하지 않는다. 같은 메뉴를 왼쪽 문서형 작성 영역에도 사용하고, 왼쪽 메모는 해당 QT의 필드·문자 범위에 저장한다. 하이라이트와 서식은 해당 QT에만 표시한다. 성경 화면에는 강조 색상을 보이지 않는다. 메모는 사용자/책/장/절/문자 범위를 기준으로 공유하고 노란색 점선 밑줄, 마우스 오버·포커스 오버레이로 표시한다. 범위 텍스트가 바뀐 경우 잘못된 위치에 표시하지 않는다. 메모 오버레이는 --surface/--line/--r-surface/--shadow를 사용하고 편집 창에는 메모·취소·저장을 둔다. 임의 HTML 입력은 허용하지 않으며 키보드 Escape로 메뉴·메모를 닫는다.

QT 본문은 생성 시 스냅샷으로 저장하고 기존 기록을 외부 재조회로 덮어쓰지 않는다. 만들기 실패 시 실제 오류와 재시도·직접 기록을 제공하며 임의 본문은 생성하지 않는다. 자동 저장 실패·버전 충돌 시 입력을 유지하고 화면 이동 전에 저장·재시도를 수행한다. 실제 공급자 접속 검증과 합성 응답 테스트를 구분한다.

구현은 src/features/scripture-workspace.js, src/domain/scripture.js 및 bible.js, server/scripture.js, server/notion-scripture-import.js, server/daily-qt.js를 사용한다. QT 양식은 src/features/qt-editor.js, 안정적인 항목·구절 식별은 src/domain/qt-journal.js, 공용 구절 주석은 src/features/bible-annotations.js와 src/domain/verse-annotations.js, 선택·우클릭 메뉴는 src/features/scripture-selection-menu.js, 왼쪽 작성 서식·메모는 src/features/qt-writing-menu.js, 저장 대기·재시도·이탈 보호는 src/features/scripture-drafts.js에서 구현한다.

### Document editing menus

문서 편집 메뉴는 기존 워크스페이스와 같은 색상·타입·컨트롤 토큰을 사용한다. 메뉴 크기를 조정할 때 세로 선택 패널, 블록 작업 목록, 옆으로 열리는 하위 메뉴, 색상 격자라는 형태와 기존 작동 방식은 유지한다.

앱 화면 전역에서 우클릭하면 우클릭 위치에 공통 메뉴를 표시한다. 키보드의 Context Menu 키와 Shift+F10도 지원한다. 입력 중에는 잘라내기·복사·붙여넣기·모두 선택을, 텍스트·링크·이미지 위에서는 가능한 복사 동작을 제공한다. 그 외 화면에서는 새로고침과 화면 위/아래 이동을 제공한다. 문서 블록은 기존 블록 전용 메뉴를 계속 열고, 텍스트 선택 서식 메뉴는 선택 범위에 붙는 별도 도구 모음으로 유지한다.

전역 메뉴와 문서 블록 메뉴는 폭 240px, 패널 안쪽 여백 4px, 선택 행 데스크톱 최소 36px / 900px 이하 최소 44px, --text-body(14.5px), 18px 동작 아이콘, --r-surface(14px), --r-control(9px)을 공유한다. 항목은 세로 6px·가로 10px 패딩과 8px 아이콘 간격으로 조밀하게 배치한다. 서식 선택 도구 모음은 폭 240px, 패널 안쪽 여백 4px, 18px 아이콘으로 맞추고 5열 아이콘 격자 간격은 2px로 둔다. 아이콘 동작은 데스크톱 36×36px / 900px 이하 44×44px로 둔다. 색상 격자는 패널 여백 8px, 칸 간격 4px로 줄여 높이를 다듬되 32px 견본과 5×2 배열은 유지한다. A 색상 버튼과 팔레트 선택 상태는 현재 선택 범위의 텍스트 색·배경색을 실시간으로 반영한다. 색상 하위 메뉴도 `document-color-grid`로 열어 텍스트색과 배경색을 각각 5×2 격자로 표시하고, 견본은 32px를 유지한다. 화면 가장자리에서 8px 이상 떨어지게 위치를 보정하고, 높이는 화면에 맞춰 스크롤한다. 흰 표면, 구분선, 얕은 그림자, 회색 호버 배경을 사용하며 Escape와 방향키로 조작한다.

블록 핸들 또는 우클릭으로 작업 메뉴를 연다. 검색, 전환, 색상, 복제, 삭제와 클립보드·블록 추가·정렬 동작을 제공한다. 옮기기·위로 이동·아래로 이동 메뉴는 두지 않으며 블록 핸들 드래그와 Alt+위/아래로 재정렬한다. 색과 블록 링크 복사 사이에 정렬을 두고 삭제는 최하단 붉은색으로 표시한다. 전환·색상 하위 메뉴는 옆에 배치하고 화면이 좁으면 반대쪽으로 조정한다. 텍스트 선택 메뉴는 선택한 범위를 유지한 채 서식을 적용하며 색상 격자는 패널 위에 붙인다. 최근 사용 색상은 최대 5개를 현재 실행 중인 편집 세션에서 표시한다. 문서의 텍스트·배경 색상은 콘텐츠 서식이므로 프로젝트 식별용 6색 팔레트와 구분한다.

선택한 블록은 --selected 배경으로, 현재 서식 값은 체크 또는 견본 외곽선으로 표시한다. 방향키·Enter·Escape와 외부 클릭 동작을 유지하고, 키보드 포커스는 공통 2px 잉크색 외곽선·4px 오프셋을 사용한다. 아이콘 전용 동작에는 접근 가능한 이름과 툴팁을 둔다. 댓글은 선택 본문에 연결해 작성·저장·조회할 수 있는 실제 기능이다. 텍스트 선택 메뉴는 정렬과 별도 복사·잘라내기·붙여넣기 줄을 제공하며 서식 지우기·AI 편집·더보기 항목은 표시하지 않는다. 지원하지 않는 동작을 성공으로 표시하지 않는다. 메뉴 변경으로 저장 방식, 문서 내용, 레퍼런스 연결이나 터치 드래그 지연을 바꾸지 않는다.

구현 출처는 src/features/document-menus.js(메뉴·아이콘 매핑), src/features/documents.js(편집 동작 연결), src/workspaces.css(메뉴 스타일), src/design-system/primitives/icons.js 및 icons/editor-paths.js(공통 아이콘팩)다.

### Project and workspace settings
프로젝트 설정은 넓은 화면에서 이름 → 색상·아이콘 → 설명을 왼쪽에 두고 촬영일 → 시간 → 장소를 오른쪽에 둔다. 작은 화면에서는 같은 순서로 세로 배치한다. 색상과 아이콘 설정은 라벨을 위쪽에 정렬하며 내부 세로 구분선을 만들지 않는다. 프로젝트 모양 선택에서는 아이콘을 왼쪽, 색상 팔레트를 오른쪽에 둔다.

계정·데이터·외부 앱 연결·관리자 정보는 속성명과 값/동작을 정렬한다. 로그아웃은 계정 설정 하단의 구분선 아래 위험 동작으로 둔다. 공유 프로젝트는 있을 때만 표시하며 불러오기에 실패하면 재시도를 제공한다.

### Equipment and Materials workspaces
자료 워크스페이스는 모든 자료와 레퍼런스를 제공하며, 대여소는 장비 워크스페이스에 둔다. 장비 워크스페이스 사이드바는 멤버 장비 / 조직 장비 / 장비 도감 / 대여소로 구성한다. 대여소는 장비 도감과 같은 카드형 갤러리로 탐색하고, 검색과 추가 동작은 갤러리 상단에 둔다. 카드를 열면 대여소 정보를 기존 폼으로 확인·편집한다. 빈 상태에는 대여소 추가 동작을 제공한다.

조직 장비의 탐색 순서는 **장비 목록 / 반출 신청 / 반출 현황 / 반출·반납 내역 / 조직 관리**다. 조직 선택은 검색 드롭다운으로 제공하며 탭 이동과 새로고침에서도 선택 조직을 유지한다. 멤버 장비에는 반출·반납 기능을 제공하지 않는다.

멤버·조직 장비는 공통 장비 요약, 검색 목록, 선택 항목 상세와 편집 동작을 사용한다. 장비 등록은 버튼에서 입력 창을 연다. 장비 관리 목록은 카메라·렌즈·조명·삼각대·SD 카드·음향·기타 순으로 묶는다. 프로젝트 장비 상태는 ‘사용하기’와 ‘✓ 사용 확정’으로 구별한다. 장비 도감은 제조사·정식 이름·별명·사진을 제공하고 소유자나 재고는 표시하지 않는다. 사진이 없으면 ‘사진 없음’을 표시한다.

### Administration and people
사용자 관리는 가입자 / 조직 / 비가입자 그룹으로 구성한다. 목록에서 항목을 고르면 하나의 편집 화면으로 이동하며 목록 복귀 동작을 제공한다. 멤버 정보의 ‘호칭’과 프로젝트에서 맡는 역할은 구분한다. 프로젝트 역할과 콜타임은 해당 프로젝트의 멤버 항목에서 관리한다. 기존 저장 값을 새 UI 의미로 자동 삭제하거나 다른 필드로 옮기지 않는다.

회원 초대는 관리자 워크스페이스의 별도 메뉴에 둔다. 팀 생성·멤버 초대·팀 배정은 프로젝트의 멤버 탭에서 관리한다. 내부 권한 키 super_admin의 화면 표기는 ‘대표’로 통일한다. 마지막 프로젝트를 지우면 가짜 프로젝트 대신 ‘프로젝트가 없습니다.’와 프로젝트 추가 동작을 보여준다.

## 7. Quality checks

새 화면이나 공통 스타일 변경을 검토할 때 확인한다.

- 3초 안에 현재 상태와 다음 행동을 알 수 있는가?
- 제목·주요 동작·탭의 위치와 위계가 기존 워크스페이스와 같은가?
- 색상 없이도 상태와 선택을 구별할 수 있는가?
- 키보드 포커스, 접근 가능한 이름, 작은 화면의 44px 조작 목표를 제공하는가?
- 760px 이하에서 리스트/상세가 한 열로 바뀌고 탭·텍스트가 잘리지 않는가?
- 같은 역할의 컨트롤이 공통 토큰과 컴포넌트를 사용하는가?
- 새로 쓰거나 수정한 디자인 자산의 출처와 라이선스를 기록했는가?



감사·기도제목 화면은 QT의 원본 항목을 날짜별로 묶어 최신 날짜부터 보여준다. 공통 워크스페이스 여백과 검색·목록 행을 사용하고 기도제목에는 전체 / 나의 기도 / 다른 사람을 위한 기도 필터를 둔다. 항목은 원본 QT를 열고 목록으로 돌아오면 수정 내용을 다시 조회한다. 별도 사본을 만들지 않으며 사용자별 비공개 조회와 페이지 조회를 유지한다. 날짜는 --text-support·500, 내용은 --text-body·400을 사용한다.

성경 분할 읽기는 번역만 좌우에서 별도로 고르고 책·장·검색 위치와 절 선택은 공유한다. 양쪽 중 어디에서 이동하더라도 동일한 위치로 이동한다. 절은 책/장/절 주소로 대응시키고 더 긴 본문·소제목 높이에 맞춰 행을 정렬한다. 번역에 없는 절은 빈 대응 행으로 남긴다. 글자 크기·창 크기·주석 높이 변경 후에도 다시 정렬하며 760px 이하의 세로 배치에서는 높이를 강제하지 않는다. 연속 선택은 첫 클릭을 고정 기준으로 삼고 마지막 클릭까지의 절만 양쪽에서 선택한다(역방향 포함). 예를 들어 1→10→7이면 1–7절만 남는다. 본문 바깥의 빈 영역을 클릭하면 선택과 기준점을 해제하고, 장 이동 시에도 초기화한다. 선택 배경은 절 행의 빈 정렬 공간까지 채우고 구간의 위·아래 끝만 둥글게 처리해 하나의 면으로 표시한다. 번역 변경과 분할 보기 전환은 선택을 유지한다. 처음 읽을 때 책 목록과 본문을 함께 받고, 동일 요청은 합치며, 원문 번역 파일은 계정·번역별로 IndexedDB에 저장해 새로고침 후에도 장 이동·검색·분할 보기에 재사용한다. 처음에는 필요한 장부터 표시하고 선택 번역과 비교 번역의 전체 원문을 백그라운드에서 받는다. 파일 개정은 콘텐츠 해시로 확인하고 서버 확인을 기다리지 않고 저장본을 먼저 표시한다. 브라우저 저장소를 쓸 수 없으면 메모리 캐시와 서버 조회로 동작한다. 사용자 메모·주석·QT 기록은 원문 캐시에 포함하지 않는다.

### 사이드바 접기와 순서 변경

1단 레일에서 현재 워크스페이스 아이콘을 다시 누르면 2단 사이드바만 접고, 다시 누르면 펼친다. 다른 워크스페이스를 열 때는 2단도 펼친다. 본문·문서 편집기를 다시 렌더링하지 않아 입력·선택 문서·URL을 유지한다. 데스크톱에서는 접힌 폭만큼 본문을 넓히고, 작은 화면에서는 완전한 캡슐형 플로팅 바(56px)와 원형 뒤로가기·필요한 전체 목록 탐색을 사용하고 Escape는 이전 화면으로 복귀한다. 아이콘에는 aria-expanded·aria-controls를 제공하고 숨긴 패널은 포커스 대상에서 제외한다.

1단 워크스페이스와 2단 기능 메뉴는 순서를 고정한다. 1단은 홈 / 말씀 / 구분선 / 프로덕션 / 장비 / 자료 순서이며 설정은 아래에 둔다. 관리자 기능은 별도 워크스페이스 없이 설정의 데이터 다음 구분선 아래에 두고, 사용자 관리(가입자·조직·비가입자 및 최고 관리자 전용 권한 관리), 회원 초대, 권한이 있는 전체 프로젝트를 기존 역할 기준으로 표시한다. 일반 사용자에게는 관리자 항목과 구분선을 표시하지 않는다. 기존 관리자 URL은 사용자 네임스페이스의 settings 경로로 정규화하며 서버 권한은 변경하지 않는다. 말씀 아래 구분선은 모바일 하단바에도 표시한다. 1단 좌우 여백은 10px이며 2단 패널의 왼쪽 위·아래 모서리를 20px로 처리해 안쪽 경계를 둥글게 만든다. 프로젝트 목록과 공유 프로젝트 목록만 직접 드래그해 순서를 바꾼다. 마우스는 5px 이동 후, 터치는 320ms 길게 누른 뒤 시작한다. 길게 누르기 전의 터치 이동은 스크롤로 처리한다. 원래 항목을 옅게 남기고 커서를 따라가는 동일 크기의 복제 미리보기와 파란 삽입 선을 표시한다. 놓으면 순서를 적용하고, Escape·범위 밖 놓기·포인터 취소 시 복구한다. 드래그 직후에는 항목 클릭으로 이동하지 않는다. Alt+위/아래 방향키로도 순서를 바꿀 수 있다. 2단은 프로젝트·공유 프로젝트 그룹 안에서만 정렬하며, 권한과 프로젝트 원본 데이터는 바꾸지 않는다. 순서와 데스크톱 접힘 상태는 계정별로 현재 브라우저에 저장하고, 새 항목·권한 변경에도 사용 가능한 항목만 표시한다.

### 홈의 개인 Google Calendar

홈의 ‘내 일정’은 연결한 사용자 본인의 읽기 가능한 기존 Google 캘린더를 골라 조회한다. 프로젝트 멤버에게 개인 일정을 복사하지 않는다. ‘프로젝트 일정 게시’에서는 각 프로젝트의 쓰기 가능한 기존 대상과 게시 시작 날짜를 직접 선택한다. 해당 캘린더의 공유 열람자에게 프로젝트 일정이 보일 수 있음을 확인한 뒤 게시를 시작한다. 대상 변경 시 기존/게시 시도 일정은 원래 대상에서 유지·갱신하고 새 일정부터 새 대상을 사용하며, 삭제·이동·복제를 자동 전파하지 않는다. 연결 승인·권한 부족·만료·재시도와 건너뛴 일정은 실제 상태로 표시한다.

## Google Tasks 연결

설정 → 연결의 Google Tasks 패널은 기존 목록과 연결할 Studio 할 일을 명시적으로 선택한다. ‘모든 할 일’은 현재·향후 항목 모두임을 표시한다. 완료 충돌은 양쪽 상태와 적용 버튼을 함께 표시하고 재확인한다. 시간·반복·하위 계층 제한과 삭제 미전파를 연결 안내에 둔다. 모바일 입력·버튼은 기존 44px 기준과 화면 너비를 유지한다. 개인 Google 데이터는 프로젝트 화면에 표시하지 않는다.

Calendar·Tasks·Sheets·ChatGPT 연결 관리는 설정 → 연결의 서비스별 카드에 모은다. 계정과 상태, 연결/재연결/해제 동작을 표시하고 설정 안내는 접어 둔다. 홈은 개인 일정과 연결한 할 일 콘텐츠 및 연결 설정 링크를 유지한다. 프로젝트 게시·동기화 범위를 바꿀 때 권한·공유 영향 확인을 유지한다.

Google 연결은 설정 → 연결에서 카드 하나와 연결/재연결 버튼 하나로 제공한다. Calendar·Tasks·Sheets 권한 및 실제 동기화 상태를 구분하고 일부 동의 시 기존 연결 유지 여부를 표시한다. 일정 게시·할 일 범위는 접은 섹션에서 관리하며 동의·공유 영향 확인은 유지한다. 홈 일정·할 일에는 연결 버튼·설정 링크·연결 안내 카드를 표시하지 않고 콘텐츠 또는 간단한 빈 상태만 표시한다.

성경과 QT의 성경 본문은 system-ui 기반 고딕체(Apple SD Gothic Neo / Noto Sans KR / Malgun Gothic 대체)를 사용하고 400 두께·1.85 행간·일반 자간으로 읽는다. 글자 크기 조절과 양쪽 절 정렬은 유지한다. 성경 저장소의 일부 파일 가져오기 오류는 본문 하단 상태 메시지로 반복하지 않고 상단의 접힌 ‘성경 불러오기 상태’에서 상세를 확인한다. 읽을 번역이 없으면 이 안내를 펼쳐 표시하고, 이후 조회·편집 오류는 기존 상태 영역에 계속 표시한다.

장비 사이드바는 멤버 장비, 조직 장비, 구분선, 장비 도감, 구분선, 대여소 순서를 데스크톱·모바일에서 동일하게 유지한다. 개인 장비 보관함 선택과 기존 권한별 표시·이동 동작은 유지한다.
### 추가·빈 상태 카드

레퍼런스와 QT의 새 항목 만들기에는 공통 `addSurface` 표현을 사용한다. 기존 surface 색과 둥근 모서리 토큰 위에 얇은 1px muted 회색 점선 외곽, 넉넉한 안쪽 여백, 가운데 가는 + 아이콘, 간결하고 밝은 행동 제목을 세로로 배치한다. 필요하면 보조 설명 한 줄을 muted 색으로 둔다. 레퍼런스 제목은 ‘레퍼런스 추가’, QT 제목과 날짜는 현재 선택한 날짜의 맥락을 유지한다.

카드 전체가 하나의 네이티브 button이며 클릭·Enter·Space로 기존 추가 흐름을 연다. 중첩 버튼을 두지 않고 포커스를 분명히 표시한다. 읽기 전용 화면에는 동작 없는 빈 상태만 표시한다. 이 카드는 일반 36/44px 버튼이 아닌 넓은 내용 표면이므로 공통 버튼 높이·패딩 규칙으로 축소하지 않는다. 항목이 이미 있는 카드·행과 편집·저장 동작은 그대로 유지한다. 구현은 `src/design-system/primitives/add-surface.js`와 `.add-surface`를 재사용한다.

자료 선택은 파일·링크·소유 문서, 레퍼런스 목록, 프로젝트 연결 자료, 레퍼런스 보드·첨부 각각의 범위 안에서 동작한다. 열기 버튼과 별도의 체크박스를 제공하고 선택 개수·현재 목록 전체 선택·선택 해제를 표시한다. 검색·필터 변경 시 선택을 비우며 삭제 전 개수와 복구 불가 여부를 확인한다. 프로젝트에서는 원본 삭제 대신 연결 해제, 보드·첨부에서는 파일 원본을 보존하는 제외로 표시한다. 읽기 전용 레퍼런스는 선택·삭제 UI를 노출하지 않으며 빈 목록의 기존 점선 추가 표면을 유지한다. 여러 요청의 부분 실패는 삭제된 개수와 남은 항목을 구분해 알린다.

설정 메뉴는 계정 설정 / 앱 설정 / 연결 / 데이터로 구분한다. 화면 모드는 앱 설정에만 표시하며 사용자 경로 `/:username/settings/app`에서 기존 브라우저 저장값과 탭 간 동기화를 유지한다.
화면 모드는 기존 파란 accent·selected 색상 토큰의 스위치를 사용하며 라이트는 해, 다크는 달 아이콘과 상태 문구로 구분한다. 참고 이미지의 별도 팔레트는 사용하지 않는다. 네이티브 버튼의 키보드 조작·포커스와 동작 줄이기 설정을 유지한다.
강조색은 파랑(기본)·보라·초록·주황 네 가지이며 브라우저 `studio.accent.v1`에 저장하고 탭 간 동기화한다. 라이트·다크별 대비를 갖춘 accent/selected/blue 토큰으로 버튼·선택·포커스를 맞추며 의미 색상과 사용자 콘텐츠 색상은 보존한다.

QT·말씀 목록은 반응형 갤러리로 제목과 날짜 · 성경 범위(passage) 두 줄만 표시한다. 별도 체크박스 선택 후 선택 개수·삭제·취소를 표시하며 필터 변경은 선택을 초기화한다. 삭제는 기존 소유권·revision 검사와 복구 불가 확인을 유지한다. 오늘 QT 추가 표면에는 조회한 성경 범위를 날짜와 함께 표시하고 조회 실패는 본문 확인 불가로 알린다.

성경 대조는 데스크톱에서 두 번역을 좌우로, 760px 이하에서는 같은 절의 주 번역 다음에 대조 번역을 배치한다. 실제 절 번호로 짝을 맞추며 누락 절은 기존 표시를 보존한다. 구절 찾기는 기존 번역 범위의 책·장·절 세 열을 독립 스크롤하고 책 이름·한글 초성 검색을 지원한다. 책·장 선택은 임시 상태이며 취소는 읽기 위치를 바꾸지 않는다. 절 선택은 즉시 해당 위치로 이동한다.

성경 읽기 상단에는 현재 책·장(구절 선택기 열기)과 기본 | 대조 번역 선택만 표시한다. 번역 선택은 기본·대조 두 열의 라디오 선택과 체크 표시, 대역 없음·즉시 반영·닫기를 제공하며 기존 번역만 사용한다. 이전 장·다음 장은 본문 끝의 좌우에 두고 이동 후 상단 읽기 위치로 돌아온다. 별도 인라인 검색·대조 버튼·글자 크기 버튼은 표시하지 않는다. 성경 본문 글자 크기는 앱 설정의 -3~+3 범위와 실시간 미리보기에서 관리하고 `studio.bibleFont.v1`로 브라우저·탭 간 저장한다.
구절 찾기 선택지는 개별 테두리 없는 행이며 선택 강조와 포커스를 유지한다. 구약은 율법서/역사서/시가서/대선지서/소선지서, 신약은 복음서/역사서/바울서신/일반서신/예언서 순으로 실제 책만 분류한다.
모바일 하단 워크스페이스 바는 접근성 이름·툴팁을 보존하는 아이콘만 표시한다. 앱 뷰포트 바닥과 안전 영역까지 pointer-events 없는 흐림·그라데이션을 이어 주며 마지막 콘텐츠를 스크롤할 공간을 확보한다. 브라우저 자체 UI는 변경하지 않는다.

구절 선택기는 본문보다 분명한 굵기의 구약·신약 제목과 세부 분류를 사용한다. 책·장·절 선택은 앱 강조색과 별도로 둥근 파란 배경을 사용하며 절을 누르면 추가 이동 버튼 없이 즉시 해당 위치를 연다. 대상 절은 렌더링 후 3초간 강조하고, 새 이동·화면 이탈은 이전 타이머를 취소한다. 같은 절의 두 번역은 함께 강조한다.
번역 선택은 기본·대조·대역 없음 모두 즉시 반영·브라우저 저장하고 선택창을 유지한다. 적용 버튼 없이 닫기로 끝내며, 늦게 도착한 응답은 최신 선택을 덮어쓰지 않는다. 읽던 절과 스크롤 위치를 보존한다. 대조 번역은 반복 이름·세로선 없이 약간 연한 본문색으로 표시한다.
연속 선택은 구절 사이 여백까지 한 강조 영역으로 연결하고 첫 구절 위 양쪽·마지막 구절 아래 양쪽만 둥글게 한다. 단독 선택은 네 모서리를 둥글게 하며 떨어진 선택 사이 본문과 주석은 강조하지 않는다. 모바일 페이지·헤더·탭·전체 화면 메뉴의 수평 여백은 360px 이상 28px, 더 좁은 폭은 24px이며 내용 내부에 중복 적용하지 않는다. 대화상자와 스크롤 표·캔버스는 각자의 사용 가능한 폭을 유지한다.

터치가 주 입력인 기기에서는 일반 페이지의 핀치·더블탭 확대를 가능한 범위에서 제한하되, 한 손가락 스크롤·텍스트 선택·입력 및 앱 내부 캔버스 확대는 유지한다. 데스크톱 뷰포트는 바꾸지 않는다. 입력 글자는 모바일에서 최소 16px로 유지하고 앱의 글자 크기 설정은 계속 제공한다. 브라우저·OS 접근성 확대나 iOS 정책이 페이지 제한을 무시하는 경우까지 차단한다고 표시하지 않는다.

모바일 하단 흐림은 플로팅 pill 내부에 한정하지 않는다. body 직속 배경과 하단바는 같은 CSS 바닥 기준·공통 크기를 사용하고, 스크롤이나 JS 프레임에 의존해 위치를 다시 계산하지 않는다. 배경은 바보다 48px 위에서 부드럽게 시작해 바닥 아래 최소 160px·안전 영역·작은/큰 뷰포트 차이를 덮는다. 마스크가 있는 블러와 마스크 없는 색상층을 분리하며, pill 하단부터는 앱의 --bg·루트 캔버스·theme-color와 일치하는 불투명 색으로 빈틈을 막는다. 바깥 아래 그림자로 바닥 색을 달리 만들지 않는다. 아이콘·터치 영역은 위에 선명하게 유지하고 배경은 pointer-events:none·aria-hidden이며 메뉴·대화상자·키보드·데스크톱에서는 숨긴다. 앱이 렌더링할 수 있는 범위만 처리하고 Safari 자체 주소창·OS 표면을 변경한다고 설명하지 않는다.

홈의 개인 일정은 읽기 가능한 전체 Google 캘린더의 현재 시간대 기준 이번 달을 처음에 자동 조회한다. 캘린더·날짜 선택은 즉시 다시 조회하며, 캘린더 선택은 Studio 계정별 브라우저 환경설정으로 유지한다. 일정에 출처 캘린더를 표시하고 수동 조회는 짧은 읽기 캐시를 우회한다. 실패는 빈 일정으로 숨기지 않고 오류와 재조회 동작으로 표시하며, 이전 요청이 최신 선택을 덮어쓰지 않는다. 개인 일정 조회는 프로젝트 캘린더 게시·연결 권한을 변경하지 않는다.

모바일 root·하위 pill의 양 끝은 높이의 절반 이상인 캡슐 반경이며, 별도 뒤로가기는 동일한 56px 원형이다. 모든 아이콘 버튼은 최소 44px 터치 영역·접근성 이름·포커스를 유지하고 좁은 화면의 프로젝트 탭은 가로 스크롤한다. 하단 뒤로가기는 기존 이동·저장하지 않은 변경 확인을 거쳐 홈 대시보드와 기본 바로 이동한다. 브라우저 뒤로·앞으로는 기존 이력대로 복구하며 데스크톱 레일·사이드바 구조는 바꾸지 않는다.

모바일 하단 탭의 선택 표시는 약 170ms로 이동하고 아이콘은 한 번만 작게 움직인다. root·하위 전환은 내부 아이콘만 짧게 나타내며 고정 바 전체와 바닥 흐림 레이어는 이동시키지 않는다. 탭 순서상 오른쪽 항목을 고르면 새 본문은 오른쪽에서 왼쪽으로, 왼쪽 항목은 반대로 약 18px·170ms 진입한다. 기존 경로와 읽기 위치를 보존하며 빠른 재선택은 이전 모션을 정리한다.
하단 탭은 누른 채 가로로 10px 이상 이동하면 선택 미리보기를 표시하고 놓을 때 기존 이동 동작을 한 번만 실행한다. 세로 스크롤·바깥 텍스트 선택·화면 가장자리 제스처를 방해하지 않고 영역 밖 놓기·취소·Escape·포인터 유실은 이동하지 않는다. 원형 뒤로가기와 더 보기는 드래그 선택 대상에서 제외한다. 좁은 pill 끝에서는 가로로 스크롤해 가려진 탭도 접근한다. 모션 줄이기 설정에서는 방향 슬라이드·아이콘·선택 표시 애니메이션 없이 상태만 즉시 반영한다.
설정의 연결은 플랫폼 이모지 대신 공통 Ionicons `link` 체인 SVG를 사용한다. 데스크톱 목록과 모바일 하위 탭·더 보기는 같은 소스를 공유하고 선택 전후 바깥 크기와 중심을 유지한다.
설정의 계정 설정은 한 사람의 head-and-shoulders `person`, 데이터는 타원형 윗면과 곡선 층을 가진 원통형 `database`(Ionicons `server`)를 사용한다. 멤버·사용자 관리의 그룹 아이콘은 유지하고 데스크톱·모바일·더 보기에서 같은 outline/filled 쌍을 공유한다.

모바일 홈 하위 탐색과 보조 목록에는 홈만 표시하고 일정·할 일은 숨긴다. 해당 주소와 홈 대시보드의 일정·할 일 콘텐츠 및 동기화는 유지한다. 직접 주소로 열었을 때도 단일 홈 선택과 원형 홈 복귀를 표시하며, 홈에 이미 있으면 복귀가 중복 이력을 만들지 않는다. 관리자 버튼은 일반 사용자에게 표시하지 않고, 관리자 목록에서도 기존 역할별 항목만 표시한다. 일반 설정 네 항목은 하위 바에서 계속 접근한다.

레퍼런스 보드는 폭을 기준으로 크기가 정해지는 콘텐츠 모듈의 흐름으로 표시한다. 사진·영상은 원래 비율과 자동 높이를 유지하고 텍스트는 줄바꿈한다. 모듈 왼쪽 여섯 점 핸들은 이동, 가까운 +는 모듈 추가, 제목 입력과 ×는 이름 변경·배치 제외다. ×로 제외한 자료·텍스트는 보관 자료에서 복원하며 파일 원본을 삭제하지 않는다.
열 컨테이너는 테두리 없이 2–4열을 담고 각 열에 여러 모듈을 넣을 수 있다. 모듈 오른쪽 가장자리 드롭은 새 열, 열 안쪽 드롭은 같은 열 안 이동, 행 아래의 전체 폭 파란 표시선은 열 밖 이동을 뜻한다. 비어 있는 열은 정리하고 한 열만 남으면 일반 흐름으로 펼친다. 모듈 가장자리·폭 슬라이더와 열 폭 슬라이더를 제공하며 이동 버튼·선택 상자·키보드로도 조작한다. 모바일에서는 열을 세로로 쌓고 저장된 폭 비율과 순서는 유지한다.
기존 공간 배치는 원래 좌표를 항목 메타데이터에 남긴 채 같은 행의 2–4개 모듈을 기존 폭 비율의 열로 옮긴다. 단독 항목은 기존 폭을 유지하며, 겹치거나 4개를 넘는 불규칙 행은 위·왼쪽 순서의 안정적인 일반 흐름으로 표시한다.

말씀 노트의 목록·검색·분류 선택에서는 QT를 제외한다. 저장된 QT와 QT 전용 화면·감사·기도제목·직접 열기 기능은 유지한다. 모든 일정에는 기존 프로젝트 달력과 같은 월간·주간·일간 UI와 목록 전환을 제공한다. 프로젝트 촬영·일정·날짜가 있는 할 일과 접근 가능한 개인 Google 일정을 출처와 함께 표시하며 Google 조회 실패 시 Studio 일정을 유지하고 오류·다시 조회를 표시한다. 보기·기간은 계정별 브라우저에 저장하고 기존 모바일 탐색 메뉴는 유지한다.
설정 → 연결의 Docs·Forms는 각각 선택적으로 읽기 권한에 동의하고 편집 화면 URL/ID로 제목과 읽기 가능 여부를 확인한다. 이 권한은 접근 가능한 파일 전체에 적용됨을 설명하며 파일 목록·문서 편집·설문 응답 조회는 제공하지 않는다. 기존 Calendar·Tasks·Sheets 연결 버튼의 요청 권한은 유지한다.

학교 워크스페이스는 학점 현황 / 학기·강의 / 할 일 / 일정 순으로 탐색한다. 강의 안에서는 강의 내용 / 할 일 / 일정 탭을 제공하고 모바일에서도 강의 탭을 유지한다. 학점 현황은 취득·필요·남은 학점과 수강 중·예정 추가 학점을 구분하며 필요 학점은 처음에 미설정이다. 이수 완료만 취득으로 합산하고 중복 학점 그룹·졸업 판단의 한계를 해당 위치에 설명한다. 학기·강의 출처는 전체 할 일·달력에도 표시한다. 학교 기록은 계정별로 분리하고 강의 내용은 공통 문서 편집기, 일정은 기존 월·주·일 달력을 사용한다.

모든 일정의 Google 일정 제목에는 공급자·캘린더 이름 접두사를 반복하지 않는다. 출처는 우측의 접을 수 있는 캘린더 목록과 툴팁·접근성 이름에서 확인한다. 각 실제 캘린더는 색이 있는 표시 체크와 우클릭/키보드 메뉴로 Studio 색·보기 여부를 관리하며 계정별 브라우저에 저장한다. 종일 일정은 둥근 채움 색, 시간 일정은 투명 배경과 작은 왼쪽 색 선을 사용한다. 주말은 옅은 중성 배경·붉은 날짜, 공휴일은 붉은 날짜만 표시하며 명시한 공휴일 출처가 없는 날짜를 임의 분류하지 않는다. 데스크톱 달력 줌은 가로 폭을 유지한 세로 밀도 조절이며 초기화·명시적 조절 버튼을 제공한다.
말씀 노트·QT 본문은 기존 번역 선택기를 사용해 즉시 번역을 바꾸고 두 번역을 절마다 위아래로 표시한다. 번역 이름은 선택기에서 확인하며 구절마다 반복하거나 왼쪽 대조 구분선을 추가하지 않는다. 실제 원본 각주는 본문 아래에서 번역·절·표시 기호별로 연결한다. 표시 번역 변경은 QT 일지·저장 본문·메모를 다시 쓰지 않는다. 일반 성경 진입은 계정의 마지막 성공한 책·장을 복원하고 명시한 주소를 우선한다.
데스크톱 분할 본문은 좌우가 각각 키보드로 접근 가능한 독립 스크롤 영역이며 경계에서 바깥 페이지로 스크롤을 넘기지 않는다. 가운데 구분선은 영역 높이를 채우고 모바일은 일반 세로 읽기를 유지한다. 하이라이트 저장은 대기·성공 표시 없이 조용히 진행하고 실패·재시도는 계속 표시한다. 기존 보라색은 유지하며 다른 하이라이트는 저장값 변경 없이 파스텔 표시 토큰을 적용한다. 텍스트 선택 메뉴는 선택 영역을 피해 배치하고 공간이 부족하면 경계 안에 작게 배치한다. 빈 곳 클릭과 Escape로 조작 메뉴를 닫되 편집 대화상자의 저장·취소는 유지한다.

모든 일정의 도구 모음은 일·주·월을 왼쪽, 이전·오늘·다음을 전체 폭의 가운데, 세 줄 캘린더 사이드바 아이콘을 오른쪽 같은 행에 둔다. 이 화면의 목록·연간 보기와 월 입력칸은 제거하고 기존 설정은 지원되는 달력 보기로 옮긴다. 일정은 외부 창 대신 앱 안 수정 대화상자를 연다. 읽기 전용·미지원 일정은 제한 이유를 표시하며 반복은 명시적으로 확인한 개별 회차만 수정한다. 충돌·저장 실패 시 입력은 유지한다.

강의 첫 화면의 강의노트는 버튼 테두리 없는 제목 목록으로 표시하고 왼쪽 이모티콘 조작에서 한 개의 이모티콘을 추가·변경·제거한다. 제목과 이모티콘은 분리된 조작이며 문서 ID와 본문은 유지한다. 항목별 순서 화살표·더보기·너비 선택·보관 버튼과 별도 드래그 핸들은 표시하지 않는다. 행의 비조작 영역을 드래그하거나 행 포커스의 Alt+위/아래로 정렬하며 이모티콘 선택기 등 내부 조작은 재정렬에서 제외한다. 기존 보관 항목이 있을 때만 복원 목록을 표시한다. 강의계획서는 과도한 파란 배경·테두리 강조 없이 제목·짧은 설명을 둔 차분한 전체 폭 링크로 표시한다.


사이드바의 탐색 항목은 URL과 뒤로가기를 지원하는 독립 화면을 연다. 캘린더 보기·색상·기본 대상 같은 문맥 제어는 일정 화면의 우측 패널에 두고, 프로젝트 대상은 해당 프로젝트 설정 화면에 둔다.

### Calendar, credit values and navigation balance

월간 일정은 별도의 작은 글씨 13px, 날짜는 제목 역할 15px로 표시한다. 일반 앱 본문 14.5px를 캘린더에 일괄 적용하지 않는다. 주·일의 작은 시간표 글자는 추가 축소하지 않는다. 학교 학점 표의 취득·필요·남음은 14px로 읽기 쉽게 하고 입력은 데스크톱 14px, 모바일 16px로 표시한다. 최신 데스크톱 사이드바는 54px 레일에 38px 버튼·22px 아이콘, 14px 항목 간격을 사용하며 2단 항목은 최소 36px다. 모바일 하단바, 성경 읽기 설정과 문서 10pt/A4 인쇄는 이 조정에 포함하지 않는다.

### 이미지 원본과 미리보기

새 자료 이미지의 원본은 선택 파일의 바이트를 변경하지 않고 보관한다. 모든 자료 목록은 작은 썸네일을, 레퍼런스는 비율을 유지한 긴 변 최대 600px 미리보기를 사용한다. 작은 이미지는 확대하지 않는다. 원본은 명시적인 열기·확대·다운로드에서 가져온다. 파생본 생성이 불가능하거나 저장에 실패하면 원본 저장 여부와 미리보기 상태를 구분하고, 미리보기 재시도에서 원본을 중복 업로드하지 않는다. 기존 파일을 자동 재인코딩하거나 원본을 파생본으로 대체하지 않는다.

### 목록·가져오기·조회 상태

모든 자료는 검색·필터 결과를 한 페이지 최대 60개씩 표시하고 이전/다음 버튼, 전체 결과 수와 현재/전체 페이지를 제공한다. 검색·필터가 바뀌면 페이지를 처음으로 돌리고 결과가 줄면 유효한 페이지로 보정한다. 목록에는 썸네일을, 레퍼런스에는 최대 600px 미리보기를 사용하며 원본은 명시적 열기·다운로드 때 가져온다.

노션 ZIP·CSV 가져오기는 파일 선택 후 처리 상태와 취소 동작을 제공한다. 미리보기 뒤 사용자가 확인한 경우에만 저장을 요청한다. 취소는 진행 중 요청을 중단하며 이미 저장 요청을 보낸 경우 취소가 서버 롤백을 보장하지 않음을 알리고 목록에서 결과를 확인하도록 한다. 실패를 성공으로 표시하지 않고 파일을 다시 선택해 재시도할 수 있게 한다.

관리자 목록의 성공한 빈 결과, 권한 없음/세션 만료, 일시 조회 실패는 서로 다른 상태다. 실패 시 빈 목록 문구나 이전 목록을 표시하지 않고 명시적 오류와 수동 재시도를 제공한다. 재시도는 기존 권한을 유지하는 GET 조회이며 진행 중 중복 요청을 막는다. 일부 분류의 실패가 다른 정상 분류의 항목을 삭제하지 않는다. 일정 추가·수정 dialog의 접근성 이름은 실제 화면 제목과 일치한다.
