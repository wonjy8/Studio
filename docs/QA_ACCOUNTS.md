# Account and project collaboration rationale

Project account invitations reuse registered identities and immediately create a linked project member, avoiding a second registration. Account search reveals only username and display name to signed-in accounts; project invitations are owner-controlled and grant read-only project access. No invitation email is sent. Manual project roster entries remain independent. Multiple team memberships are stored separately from the private workspace snapshot.

Account administration is server-authorized against the existing configured administrator, never a client flag. Profile editing and privilege assignment are absent. Suspension and deletion revoke sessions and integrations. Deletion is a reversible tombstone that retains project/file records; restore is explicit. Password reset issues a temporary password without exposing the previous hash; affected sessions and grants are revoked. Login with a reset password is restricted to session information, logout, and password replacement. OAuth/MCP access remains blocked until the account verifies its current temporary password and chooses a different valid password; replacement revokes the temporary session. Every operation requires exact username confirmation and a reason, protects the administrator from self-lockout, and writes an audit event without passwords. No production operations or migrations are executed by this change.

Equipment is indexed from existing account-owned project inventories rather than copied into a second user-maintained database. Keys combine owner/project/local equipment ID, preventing duplicate indexing on repeated saves. Account and member links are retained when explicitly provided. Normal users see only their own indexed equipment; administrator inventory is separately authorized. Removing a project/gear item unlinks its index entry without deleting other accounts' equipment or records. A project invitation does not expose the owner's other projects or private files.

## Canonical equipment follow-up

`equipment_items` stores account-owned physical equipment identities. `equipment_links` connects one identity to each project inventory and explicit project member IDs for owner/assignee. Existing inventories register on the next validated save, retaining all legacy names and free-text ownership. Linking an existing item is idempotent per project and restricted to its owning account. Canonical name/category edits appear on subsequent project reads; project-local readiness and person assignments stay local. A workspace save uses a savepoint so rejected equipment/member IDs cannot leave partial registrations. Removing an inventory placement does not delete the canonical record or another project's usage. Equipment is never deduplicated by a guessed name; users choose reuse explicitly.

Shared project discovery is available to invitees with a read-only projection. This does not grant private owner file access or write permission. Pending acceptance/role escalation is deliberately absent until a policy is selected.
