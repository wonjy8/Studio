# Private workspace Google calendar destinations

Home, School and the signed-in account's own production projects have independent calendar publication settings. Desktop uses a current-workspace sidebar action; mobile has a header settings action. Only the already connected Google account's writable calendars are offered. This feature requests no new OAuth scope, creates no calendar and changes no remote subscriptions or ACLs. Shared-project creation/sharing is a separate feature; personal tokens and mappings are never delegated to another member.

Settings bind a CAS revision, Studio session, Google connection generation and workspace. Saving a target does not immediately publish existing data. The first setup may explicitly include existing events; otherwise a baseline excludes them and new sources publish automatically. Existing legacy project mappings are preserved. Changing targets never moves mapped events; even a pending source is reserved against the old target before retargeting. Disconnect stops publication while retaining private preferences; reconnect requires review/retry before restoring a removed link. Missing permissions, changed accounts and malformed dates/times remain actionable errors; no fallback calendar is chosen.

One existing publication engine handles conditional updates and deletion only for sources explicitly enrolled in workspace lifecycle sync. Old orphan mappings are not retroactively deleted. Stable IDs make response-loss retry idempotent. All-day dates retain exclusive ends; native timed sources retain their original mapping timezone. Provider events with unexpected markers, attendees or recurrence are not silently overwritten/deleted. No attendee notifications are requested. A manual workspace retry scopes writes to that workspace; the background cadence continues enabled workspaces. Remote deletion is not represented as undoable in Studio.

Home adds a private native event store with revision-safe add/edit/delete and deletion tombstones. Its schedule supports all-day/timed editing and projects it in the viewer timezone. Aggregate calendars suppress the signed-in account's own published Google duplicate only while its native source is successfully loaded and visible. External provider events remain independent. Imported Google data and settings are excluded from MCP.

Native `home_events` content is a bounded generic MCP resource under explicit current/future workspace consent; legacy full-content approval alone does not enable it. Reads/proposals/applies reuse existing account, scope, revision, single-use and confirmation protections. Proposals disclose that confirmed native changes can synchronize through an existing enabled Calendar setting. No Google connection settings, credentials or grant management are exposed. No live consent is activated by deployment.

Validation uses temporary accounts and mocked provider responses. It covers source/target preservation, account/connection changes, permissions, retry/response loss, conditional deletion, malformed times, all-day/DST behavior, MCP consent/replay/isolation, and desktop/mobile settings and event UI. Actual provider calendar/ACL operations are not performed for QA.
