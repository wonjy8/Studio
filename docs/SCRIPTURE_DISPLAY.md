# Scripture and QT display

Note passage panels and QT use the existing authorized translation catalog, browser Bible cache and version picker. Choices apply immediately. Both desktop and mobile place the secondary translation below the same canonical book/chapter/verse, with no repeated translation name or per-verse divider. Missing verses retain their address and an explicit empty-text marker. Selecting the same translation twice renders it once. Version names remain in the selector/header.

Display changes do not rewrite stored note documents, QT snapshots, journal content or passage addresses. Annotation offsets remain tied to their exact quote and canonical verse; different translations cannot shift annotations onto different words. Within a dual passage display, views of one verse share a single annotation model/save revision, so rapid edits on either translation do not race separate writes. Pending note/annotation changes flush before translation changes or navigation.

Footnotes come only from explicit inline note definitions already present in the authorized translation text, parsed with the existing Bible presentation parser. They appear below the passage, grouped by translation, with verse/marker links in both directions. Translations/passages without note definitions have no generated explanatory notes. No external corpus or supplementary commentary is imported.

The server stores the last successfully viewed book/chapter per signed-in account in an additive `scripture_reading_positions` table. Normal initial rendering does not overwrite this position. Explicit book/chapter/verse URLs and a newly selected passage take priority. The server rejects nonexistent source/version chapters; failed/empty reads are not persisted. Translation preferences retain their existing account-partitioned browser storage.

Desktop split layouts use bounded native per-pane scrolling and overscroll containment, with focusable panes and a full-height QT center divider. The outer split page is bounded; stacked mobile layouts retain ordinary page scrolling. No broad wheel cancellation is used. Selection menus prefer free space above/below the selection, flip/shift inside the active pane, and recalculate during scrolling/resizing. Dense selections can require a compact bounded fallback; the UI does not promise that every nearby text line remains unobscured.

Quiet annotation autosave retains debounce, pending guards and revision checks. Routine pending/saving/success labels stay hidden; failures remain visible with retry until persistence succeeds. Pastel highlight rendering uses CSS tokens keyed by the existing stored colors. Purple values remain exact and stored annotation values are unchanged. Disposable menus close on outside interaction/Escape; edit dialogs keep their separate save/cancel behavior.
