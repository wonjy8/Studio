# School workspace

The private School workspace provides credit overview, semesters/courses, course documents, tasks and schedule. Desktop rail and the existing mobile workspace navigation expose Overview / Semesters / Tasks / Schedule. Course tabs expose Content / Tasks / Schedule. Namespaced URLs retain semester, course, document and tab selections across refresh and browser history.

Graduation required credits start unset. Users enter their own target; no university, major, grading scale or academic rule is inferred. Only courses explicitly marked completed count as earned. Planned/in-progress/failed/withdrawn courses do not count as earned. A user-defined duplicate-credit group counts its largest completed credit value once; empty groups count independently. For these groups, in-progress/planned totals show only potential additional credits beyond already earned/higher-priority totals. Credits use hundredths internally for aggregation. This is a user-maintained tracker, not a graduation determination: compulsory courses, major/general requirements and official recognized credits must be checked separately.

`school_workspaces` is an additive, account-owned JSON store with a separate revision. The authenticated session determines ownership; client-supplied user/owner fields are rejected. Validation bounds semesters, courses, documents, tasks, events, dates and numeric values and rejects duplicate entity IDs and dangling semester references. Concurrent edits return conflicts without overwriting data. Identical full-value retries are idempotent. Generic live-session/Origin validation protects writes. Account deletion cascades school data; project sharing, legacy workspace APIs and existing OAuth grants are unchanged. School records remain excluded from MCP until a separate explicit content decision.

The existing document editor and calendar renderer are reused. Course tasks and dated tasks/events appear in school aggregate views and the account's home task/schedule views with semester/course labels. They never enter shared project snapshots or Google publication/synchronization. All-day dates and timed single-date events are supported initially; recurring school timetables/imports are not inferred or created.

Validation: `tests/school.test.js`, `tests/school-api.test.js` and `tools/qa-school-browser.mjs`. Browser fixtures create only synthetic local accounts and records; they cover repeated create/edit/cancel, note saves, credit recalculation, calendar views, reload/back/forward, mobile navigation and account isolation. No real academic records are used.
