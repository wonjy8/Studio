# School content through MCP

School content requires separate connection-owner consent `school-content-v1` (version1). Existing grants, full-content approval and new OAuth connections do not receive School approval automatically. No Google consent, credentials, Cloud configuration or real course records are changed by deployment.

In Studio, open Settings → Connections → ChatGPT, expand School content for the intended connection, review the scope and click “이 연결에 학교 콘텐츠 허용”. Approval preserves that connection's existing read-only/read-write OAuth scope. A read-only connection can only read School; write access requires the owner to explicitly reconnect/authorize write access separately. The owner can revoke School consent independently of full-content consent and without disconnecting other services. Revocation/reapproval invalidates pending School proposals. No live approval is performed by implementation or tests.

`studio_list_projects` advertises effective School permissions and finite resources. The callable tools are `studio_read_content` and `studio_propose_content`, both with `courseId` for nested School content. Tool schema7 corrects write-flow instructions and includes canonical graduation/grade/category content. A connector showing only the old project tools cannot use these content calls even if consent is enabled. Compare its actual registered discovery catalog with the server; repeating consent or new-chat steps is not a verified fix. See [the discovery audit](MCP_DISCOVERY_AUDIT.md).

Resources: `school_overview` (canonical graduation settings, credit totals and area/GPA summaries), `school_semesters`, `school_courses`, `school_syllabus`, `school_syllabus_weeks`, `school_notes`, `school_note_blocks`, `school_modules`, `school_course_layout`, `school_tasks`, `school_events`. Nested resources require an account-owned `courseId`; item IDs must belong to that course. Notes and blocks support paged reads. Syllabus canonical name/credits/professor share course metadata. Week updates target stable IDs and preserve other weeks. Mixed course layout accepts every existing entry ID exactly once. Archive/restore preserves note bodies; destructive deletion is not exposed. Course fields include grade and creditCategory. Graduation updates preserve omitted configuration keys; supplied complete areas/mappings/gpaCourseIds replace those fields. Empty layouts on uninitialized courses are safe no-ops. New courses remain planned by default; credit status and equivalence changes appear in proposal impacts and use existing calculations, without inventing academic rules.

Read the same target first, use its revision in `studio_propose_content`, show the complete impact, obtain explicit confirmation, then call `studio_apply_changes` with confirmed:true. Proposal preview rolls back all changes. Apply rechecks live account/grant permissions, separate School consent generation and the whole School revision inside a transaction, then consumes the proposal once. Omitted fields preserve existing values, legacy documents and timestamps. A stale or expired proposal must be reread, reproposed and reconfirmed. Arrays replace full arrays, so prefer individual week/block resources when updating partial content.

School is own-account only. No owner/user selector, account/settings/admin/permission actions, file-byte downloads or uploads are exposed. Existing owned School file references may be used in modules; foreign private file IDs are rejected. School files remain separate from general files, Materials registration, startup backfill and Materials MCP. Existing full-content and other integration consent remain unchanged.

Validation uses synthetic accounts and temporary databases only: no-consent read/write rejection, opt-in isolated reads/writes across resources, missing-field/legacy preservation, immutable source timestamps, nested ownership, whole-credit changes, stale/expired/replayed proposals, consent version/revocation/reapproval, read-only grant, foreign account/file rejection, Materials exclusion, callable discovery schema and desktop/mobile consent failure/retry/reload/revoke UI. No live consent or live School content is modified.
