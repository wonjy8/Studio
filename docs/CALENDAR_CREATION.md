# Date and time range creation

The shared month grid keeps the date on the left and an add button on the right. The add button appears on cell hover/focus and remains available on touch devices; narrow day views also have the regular Add event action. Opening/canceling does not write a record. Day/week empty-grid drags accept primary mouse input only, snap to nearest15minutes, normalize reverse drags, clamp to the initial date column and preserve midnight as next-day00:00. Pointer cancellation/Escape clears preview; existing event buttons are excluded and release clicks are suppressed. Coordinates come from the actual column rectangle, including density and scroll. Touch remains native scrolling. Benign background renders preserve an active drag; privacy revocation forces removal.

Home creation uses the existing event editor, labelled “일정 추가”, with visibly grouped fields and a calendar selector. The current Home default is preselected; all connected calendars are listed, read-only choices disabled and “연결 안 함” last. An explicit per-event target is separate from workspace settings and cannot move existing mappings. This per-event override is currently Home creation; School/project creation continues to use its existing workspace/project default target. No new OAuth scope is requested.

An account-owned target row is written atomically with the Home record, with session/Google-generation context and fresh writable-calendar verification. None excludes that source from default publication too. Explicit Google destinations publish even without a Home default, without enabling or moving other schedules. Existing default publishing skips these overrides. Stable event IDs and provider-marker/ETag checks support lost-response retry, conditional update/delete, source revision races, and rejection of remote attendees/recurrence. A different Google account or lost permission records an error rather than falling back. Target settings are outside MCP; content workers cannot supply this setting field. Account deletion cascades target rows. No private file behavior changes.

If local save succeeds but publication fails, preserve the same record/ID and editable draft, lock its original destination and show actionable failure. Retrying patches that source before retrying publication. Background publication errors appear in Home calendar status. No invitations or attendee notifications are introduced.

School events gain optional endTime, with same-day ordering validation and24:00 support only as an end boundary. Legacy events remain unchanged; display/publication and the existing School content resource preserve this field. Project free-text time ranges use the same midnight boundary. Both continue to use original account/parent authorization and revision checks.

All development validation uses temporary accounts and mocked Google. Production calendars, grants, ACLs and records are untouched. Automatic Korean holidays still await a verified supplier; typography/document requests remain separate.
