# Canonical Google event project links

A project link is private owner metadata referencing one Google event. It never imports a Studio event, removes the Google original, grants project collaborators Calendar access, or enters a shared workspace/MCP project snapshot. Only the signed-in owner's own projects are eligible. Other collaborators do not receive these private projections. Unlink removes membership; it never calls Google delete and remains available using owner/canonical revision alone after a grant or original becomes unavailable. Uncertain local link writes are accepted only after authenticated private-membership read-back matches the requested IDs. Existing native project schedules and Studio-published Google projections keep their existing ownership paths.

Identity is `(Studio owner, verified Google subject, resolved calendar ID, Google event ID)`, with a stable canonical ID and old-locator aliases after a supported move. Recurrence instances have distinct event IDs; iCalUID alone is not a deduplication key. Selecting a project includes its referenced events regardless of Google-source visibility. Selecting both sources merges the same canonical ID. Linked range reads use the requested display timezone, bounded 25-entry pages (500 total), final owner/account-generation/membership checks and range-clipped targeted recovery. A disconnected or unreadable original produces an actionable warning, never a cached editable shadow or credential fallback.

## Explicit Google calendar move

The Google event editor has a collapsed Calendar change section. Selecting a writable calendar requires explicit confirmation of the original relocation and organizer change. Ordinary edits, private project membership changes and calendar moves cannot be submitted together. Repeated or cancelled confirmation does not dispatch another move. Pending/uncertain operations expose a read-only result check; the calendar view also lists durable unresolved operations across bounded pages after closing or reloading. No routine background save status is added.

Google's [move method](https://developers.google.com/workspace/calendar/api/v3/reference/events/move) changes organizer and supports default event types. Studio initially permits nonrecurring default events without attendees, with a writable organizer source and destination reachable using the same existing grant. Other cases stay explicitly unsupported; these conservative Studio boundaries are not claims that Google prohibits every such case. No delete/copy emulation or scope expansion is used. [ETag conditional modification guidance](https://developers.google.com/workspace/calendar/api/guides/version-resources) informs fresh-version checks and conditional headers. Tests use synthetic providers only; no real event move validates production behavior.

A durable, owner-bound operation receipt precedes the one move POST. Repeated requests cannot create a second move, including independent server handlers sharing the database. The move transport does not replay on a rejected access token. Uncertain outcomes use read-only reconciliation of source and destination, matching iCalUID and event content fingerprint; ambiguous results remain blocked for explicit review. Project associations retain the canonical ID and change locator only after verified completion. Existing in-memory edit leases, fresh permissions, account generations, input limits and session checks remain required. Private metadata contains no event bodies or credentials. Old location aliases cannot be edited; authenticated same-account location responses guide bounded fresh reads. Existing dirty edits are retained on a location conflict, and a changed original requires manual review. Additive tables must be included in account deletion policies; rolling back the image leaves them inert without changing legacy workspace data.
